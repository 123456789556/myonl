# P61 变更说明：做出来的东西能交出去了

## 为什么做这个

在这之前，"导出手机版"产出的是一堆文件——`index.html` + `pack.json` + 三个 js + `assets/` 目录。两个硬问题：

1. **手机上打不开**。手机上没法访问电脑上的文件夹；
2. **发不了人**。发微信只能发文件，发文件夹没人会拼。

所以之前那条链路是断在最后一步的：能写、能预览、但交不出去。这轮补的就是这一步。

## 做法：导出一个 .html

新增 `engine/webpack.build_single()`：

- 图片全部转成 `data:image/...;base64,...` 塞进素材表，播放器 `img.src = data URI` 照原样用；
- 三个播放器文件（core / layout / player）直接内联进 `<script>`；
- 剧本 IR 内联成 `window.__MYONL_PACK__`，播放器启动时**优先用它**，没有才去 `fetch("pack.json")`；
- `</script>` 这种会提前闭合内联脚本的序列统一转义成 `<\/script`；
- 结果是**一个文件**，零外部请求。

实测教程示例：**78 KB**，0 个网络请求，`file://` 双击能玩。

## 三个入口

| 入口 | 用途 |
| --- | --- |
| 菜单「文件 → 导出一个 HTML（手机能直接打开）」 | 最顺手，一键导出并直接打开 |
| UI 设计弹窗底部「单文件 · 导出一个文件」 | 和已有的「导出手机版 / 可迁移包」并排 |
| `py -3 -m engine.webpack <工程> --single <输出.html>` | 命令行 / CI |

产物落在 `<发行根>/dist/single/<工程名>.html`，编辑器里通过 `/single-file/<文件名>.html` 取回（带 `_safe_within` 越界防护）。

## 验证

| 项 | 结果 |
| --- | --- |
| 单文件产物 | 78 KB，只有一个文件 |
| pack 内联 | `window.__MYONL_PACK__=` 存在，`single: true` |
| 素材 | 全部 `data:` 开头，无 `assets/` 引用 |
| 外部请求数 | **0** |
| `file://` 打开 | 标题正确、画布有内容、能点进正文、无 JS 报错 |
| 编辑器点按钮 | 提示 `78 KB · 25 条指令 / 5 张素材`，链接可打开 |
| 菜单入口 | 请求 1 次、新开页面标题正确、能玩 |

新增测试 `tests/test_single_html.py`（8 条）：产物唯一、素材内嵌、pack 可解析、三个播放器都内联、`</script>` 转义、缺素材不硬失败、CLI、编辑器路由 + 越界。

全量 `1077 passed + 1 skipped`。

## 边界

- 图片走 base64，体积会比自己压缩的 PNG 大一些（一张 1 MB 图变 1.37 MB）。素材多的大工程会更明显，暂时没做"大图降质"。
- 音频没内嵌（教程示例没有音频；带 `@music` 的工程导出单文件后音乐不会响，会出现在 `unsupported` 提示里）。
- iOS Safari 打开本地 `.html` 需要"文件"App 里点开；微信里点 `.html` 不一定能直接跑，现实分发还是建议传静态托管或直接发文件。
