# 文档分区说明

决定一份文档放哪儿，只问一句：**这事在手机上有，还是电脑上有？**

```text
docs/
├─ mobile/     只在手机上做的事
├─ desktop/    只在电脑上做的事
├─ en/         英文入口
└─ *.md        两端都要看的（留在根）
```

## 三块分别放什么

| 位置 | 文件 | 为什么在这 |
|---|---|---|
| `mobile/` | 手机端编游戏.md | 手机端解析器的能力边界、装好的 APK 里能做什么。电脑端没有"手机能不能写这条指令"的问题 |
| `desktop/` | 打包使用指南.md | 出成品的三条口（单文件 HTML / APK / Windows 目录）主场在电脑；手机端打 APK 的例外写在 `mobile/` 那份里 |
| `desktop/` | 插件开发指南.md | `plugins/*.py` 只在电脑端 Python 运行时加载，成品里没有 Python，手机端不存在这件事 |
| `desktop/` | 开发者使用指南.md | 装环境、跑 pytest、改引擎 —— 只有电脑能做 |
| `docs/` 根 | 快速上手、产品说明书、存档与升级、素材导入指南、架构说明、engine_spec、版本规则、贡献指南、CHANGELOG | 两端都要看，或跟"在哪一端"无关 |

## 两条规矩

1. **新文档先问归属**。手机独有的进 `mobile/`，电脑独有的进 `desktop/`，说不清"只在某一端"的就放根。
2. **同一件事不要两边各写一份**。手机端的能力边界只认 `mobile/手机端编游戏.md`；电脑端怎么打包只认 `desktop/打包使用指南.md`。两边都要提的时候写一句"详见 xxx"，别抄。

## 为什么代码没跟着分

`editor/` 目录没有拆成 `editor/mobile/` + `editor/desktop/`，原因是：

- 服务端路由是按文件名逐个硬编码的（`engine/editor.py` 的 `_ROUTES`，`/editor_home.js` → `editor_home.js`），搬目录要同步改路由表；
- 离线成品（APK 内的 `gal_offline.js`）也按文件名读这些 js，搬了要同步改打包链路；
- 界面本身是同一份自适应页面（`editor.css` 里手机规则靠 media query），拆目录不会让用户看到任何区别。

所以代码层保持一个 `editor/`，用文件名的 `_mobile` / `_home` 后缀表达归属；**能一眼分开的那一层，落在文档目录上。**
