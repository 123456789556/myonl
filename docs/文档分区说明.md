# 文档分区说明

决定一份文档放哪儿，只问一句：**这事在手机上有，还是电脑上有？**

```text
docs/
├─ mobile/     只在手机上做的事
├─ desktop/    只在电脑上做的事
├─ en/         英文入口
└─ *.md        两端都要看的（留在根）
```

## 三块分别放什么

| 位置 | 文件 | 为什么在这 |
|---|---|---|
| `mobile/` | 手机端编游戏.md | 手机端解析器的能力边界、装好的 APK 里能做什么。电脑端没有"手机能不能写这条指令"的问题 |
| `desktop/` | 打包使用指南.md | 出成品的三条口（单文件 HTML / APK / Windows 目录）主场在电脑；手机端打 APK 的例外写在 `mobile/` 那份里 |
| `desktop/` | 插件开发指南.md | `plugins/*.py` 只在电脑端 Python 运行时加载，成品里没有 Python，手机端不存在这件事 |
| `desktop/` | 开发者使用指南.md | 装环境、跑 pytest、改引擎 —— 只有电脑能做 |
| `docs/` 根 | 快速上手、产品说明书、存档与升级、素材导入指南、架构说明、engine_spec、版本规则、贡献指南、CHANGELOG | 两端都要看，或跟"在哪一端"无关 |

## 两条规矩

1. **新文档先问归属**。手机独有的进 `mobile/`，电脑独有的进 `desktop/`，说不清"只在某一端"的就放根。
2. **同一件事不要两边各写一份**。手机端的能力边界只认 `mobile/手机端编游戏.md`；电脑端怎么打包只认 `desktop/打包使用指南.md`。两边都要提的时候写一句"详见 xxx"，别抄。

## 代码这一层怎么分

`editor/` 下有一个 `mobile/`，收纳**只在手机 / 平板上出现**的资产：

```text
editor/
├─ mobile/              只服务手机与平板
│  ├─ editor_home.js      书架首页（桌面端 isMobile() 早退，不接管这一层）
│  └─ home.css            首页专用样式（分组、教程引导条、空态）
└─ *.js / *.css         两端共用的底层，或电脑端专用
```

规矩只有一条：**新增界面资产前先问「这个只在手机上出现吗」**，是就进 `mobile/`，两端都用就留根。

URL 不变：`/editor_home.js` 仍然有效，服务端内部指向 `mobile/editor_home.js`，所以 `index.html`、离线成品、外部链接都不用改。

**还没分的那一半**：桌面端专用资产（`editor.css` 里的桌面规则、`editor_main.js`、`editor_pro.js` 等）仍留在根目录，因为两端共用同一份页面骨架（`index.html` + media query 分叉）。把它们拆成两套独立页面属于结构改造，会动到路由、离线包、打包链路和 1423 条测试，要单独拍板，不能顺手搬。
