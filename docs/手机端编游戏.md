# 手机端编游戏：能做什么、不能做什么

装一个 APK，打开就是编辑器。**不需要连电脑，不需要服务器。**

## 能做

| 事情 | 说明 |
|---|---|
| 新建作品 | 起个名，直接开写 |
| 写剧本 | 手机键盘输入，`.gal` 语法，缩进、`@` 指令照常 |
| 存本机 | 存在这台手机的本地存储里，不上云 |
| 改剧本 | 逐句编辑、场景视图、角色表都在 |
| 出成品 | **本机直接把剧本编成单文件 `.html`**，发给谁都能双击玩 |
| 带走剧本 | 导出 `.gal`（一份文本）/ `.json`（整个作品库） |

「出成品」走的是 `engine/parser.js` + `engine/pack.js`，和电脑端 `engine/parser.py`
逐字段一致（`tools/pack_diff.py` 拿 5 个真实工程对拍，452 条指令全部对上）。
所以**手机上打出来的包和电脑上打出来的是同一个东西**，不存在"手机版缩水"。

## 不能做（这些还在电脑上）

| 事情 | 为什么 |
|---|---|
| 塞图片 / 音乐 / 立绘 | 浏览器本地存储只有 5MB 上下，装不下素材；素材批处理（转 WebP、内嵌 base64）要电脑 |
| `@voice` `@video` `@anim` `@fg` `@cg` `@camera` `@transition` `@plug` | JS 解析器只覆盖了手机上真用得上的 15 种指令，其余遇到会**明确报错**，不会静默吞掉 |
| `@include` 引入别的文件 | 手机上的作品是**一份文本**，没有第二个文件可引 |

## 成品怎么给别人

导出的 `<名字>.html` 是一个自包含文件：播放器、剧本、素材（如果有）全在里面。

- 微信/QQ 发过去，对方点开用浏览器打开就能玩；
- 自己留着，双击也能玩；
- 想上架或做 APK，再拿到电脑上打包。

## 升级会不会把作品弄丢

不会。作品在应用私有目录的本地存储里，**签名固定**（`android/keystore/myonl-test.p12`），
覆盖安装是升级而不是换 App，存储不会被清。

保险做法：出成品前先导一份 `.json` 作品库，那是纯数据，随便拷。

## 一句话边界

手机上：**写、存、编、发**。
电脑上：**塞素材、打包成 APK、跑全量测试**。
