# P59 变更说明：手机上编辑器能用了

## 为什么改

P58 只把 UI 设计页铺满了，编辑器主界面在 390px 宽下还是三栏：活动栏 46 + 工程文件 220 + 编辑区 + 右侧预览 520。实测编辑区只剩 100 出头，写不了剧本。

## 怎么做

窄屏（≤860px）只留**编辑区 + 底部 4 个悬浮圆按钮**，其它面板全部变抽屉：

| 按钮 | 行为 |
| --- | --- |
| 📁 | 工程文件 / 章节大纲抽屉，从左滑出，宽 `min(80vw, 330px)` |
| 🗂 | 素材库抽屉，从右滑出，宽 `min(84vw, 330px)` |
| 👁 | 实时预览抽屉，从下滑出，高 `62dvh` |
| ▶ | 直接转发 `#btnRun.click()`，不起第二个运行入口 |

- 点抽屉外面（遮罩）或按 Esc 关闭；同一时间只开一个抽屉（`toggleDrawer` 先全关再开）。
- 状态栏钉在屏幕最底（30px），悬浮按钮抬到它上面，两者不叠。
- 编辑区底部留 96px，滚到底时最后几行不会被按钮盖住。
- 素材晾衣绳（`.clothesline` / `.cl-trigger`）在触屏上会被 hover 误触发并压住编辑区，窄屏直接隐藏，改用 🗂 抽屉。
- 桌面（>860px）**一行没动**：1360×900 实测 `.file-pane` 220、`.right-pane` 520、无 dock/遮罩。

## 真正的坑：390 被撑到 651

第一版上了抽屉后界面仍然错位——菜单栏看不见、`.mobile-dock` 跑到 x=461、点按钮被 `.main` 拦。诊断链：

1. `documentElement.scrollWidth = 651`，`clientWidth = 390`。
2. 遍历所有 `right > 390` 的元素，全是 `.asset-pane` 的子节点（x=392、宽 300）——素材面板靠 `position:absolute + transform` 藏在屏外，隐形地把整个页面撑宽。
3. 页面被撑宽后，`fixed` 的遮罩 / dock 跟着按 651 算，全部错位。
4. 修完 `.asset-pane`（窄屏改 `display:none`，打开时 `position:fixed` 右抽屉）后仍剩 651，最后两个 `fixed` 全屏元素（`.ob-mask` / `.mobile-mask`）仍报 651 —— 说明 layout 宽度本身被撑了。
5. 收口：窄屏给 `html, body` 加 `overflow-x: hidden; max-width: 100vw`。页面宽立刻回 390，所有 fixed 元素归位。

顺带修 `.ob-card`（新手引导卡）固定 420px 宽，在 390 屏上溢出：加 `max-width: calc(100vw - 24px)`。

还有一条：`.file-pane` 抽屉宽度一直只有 152px。原因是 `@media (max-width:900px)` 里有一条 `.file-pane{width:auto !important}`（折叠成窄条的老规则），`!important` 压过了新规则。新规则也加 `!important`，宽回到 312。

## 验证

| 项 | 结果 |
| --- | --- |
| 页面宽度（390×844） | 651 → **390** |
| 编辑区宽 | **390**（铺满） |
| 侧栏抽屉 | x -297（关）→ **46（开）**，宽 312 |
| 点遮罩关闭 | 开 → 关（-297） |
| 素材抽屉 | x 62、宽 **328** |
| 预览抽屉 | y **321**（62dvh） |
| 在手机上写剧本 | 输入后 46 行、末尾 `@end`，无 JS 报错 |
| 横屏 844×390 | 页面宽 844，按钮正常 |
| 桌面 1360×900 | 三栏原样，无 dock/遮罩 |

## 边界（没做的）

- 顶部工具条（角色 / 场景 / 运行 / 打包 / UI 设计）仍是竖排按钮文字，390 宽下要横向滑，没有收成图标 + 二级菜单。
- 底部 Dock 面板（问题 / 输出 / 运行日志）在手机上打开仍占掉半屏，没按高度自适应。
- 编辑器没有给 `<textarea>` 做手机专属键盘工具条（`@`、`@choice:`、缩进这些高频键还得手打）。
