# MYONL 产品说明书（定位与设计取舍）

> 这份只讲**产品定位、为什么这么选、历史上放弃了什么**。
> 操作步骤、指令表、打包出口分别见 [engine_spec](engine_spec.md)、[打包使用指南](打包使用指南.md)、
> [手机端编游戏](手机端编游戏.md)；代码结构见 [架构说明](架构说明.md)。能力清单以 README 与
> engine_spec 为准，不要拿本文当验收依据。

## 一、定位

MYONL 是一个**手机优先**的视觉小说制作器：作者在手机上新建作品、写剧本、导素材、本机导出
自包含成品；玩家用浏览器或安卓 APK 打开就能玩。电脑端 Python 引擎是同一套剧本的桌面内核、
预览与测试环境，不是面向普通作者的主战场。

- 剧本是纯文本 `.gal`，素材按目录约定摆放，工程可被版本管理、可被 diff。
- 成品自包含：播放器、剧本、素材打进一个文件，不依赖服务器、不强制联网。
- 引擎不锁定作者的素材与工程：目录里的图、声音、插件原样可见、可替换。

## 二、目标用户与典型场景

- 想快速把一段文字 / 图片 / 音频拼成可玩短篇，不碰编程的作者。
- 需要把作品发给别人，对方点开即玩，不需要安装运行环境。
- 在手机上利用碎片时间写剧本；复杂演出（配音、动画、镜头、转场、插件）回到电脑端完成。

## 三、关键取舍（为什么是现在这样）

| 选择 | 取舍 | 放弃的方案 / 代价 |
|---|---|---|
| 手机优先、APK 为主出口 | 作者在手机上就能完成「写 → 看 → 导出 → 发」 | 手机解析器覆盖的指令少于电脑端；高级演出必须回电脑打包 |
| 剧本纯文本 + 目录约定 | 可读、可 diff、可复用工具链；不绑定私有工程格式 | 没有拖拽式可视化脚本；作者要记有限几条指令 |
| 单文件成品 | 一个文件即可发送、存档、跨设备打开 | 素材内联成 base64 会再胖约三分之一；大素材受 40/80 MB 内存线约束 |
| 不做 iOS | 集中维护安卓 + 网页两条链路 | iOS 用户只能用浏览器打开网页成品，没有安装包 |
| 桌面内核仍保留 Python | 承载解析、运行、测试、打包与高级演出；与 JS 内核逐字段对拍 | 桌面打包只在 Windows 上验证过；不追求跨平台作者环境 |
| 插件走 `plugins/*.py` + `@plug:` | 不改内核就能加自定义指令 | 插件只在电脑端运行时加载；手机端不执行 |
| APK 是 WebView 壳，不打 NDK 原生库 | `lib/` 无 `.so`、无 ABI，包体不背重复架构 | 壳代码（dex）加 androidx/Kotlin 运行时占包体大头，未开混淆裁剪；明细见 [打包使用指南](打包使用指南.md) |
| 存档锚点是标签 + 偏移 | 剧本小改后旧存档仍可读 | 存档不保证跨大版本结构重构 |

## 四、历史上走过的方向

- 早期是桌面 Python 内核（pygame 窗口 + 目录包 exe）。这一形态保留为电脑端引擎与测试底座，
  但主目标已经从「桌面发布」转向「手机制作 + 多端成品」。
- 视频最早只支持帧序列；后来补了真视频文件通道（`@video 名 file`），帧序列仍保留给短镜头。
- 工程模板从单一示例演进为 `hello` / `default` / `standard` 三种，分别对应极简空包、教学骨架、
  内置素材成品。

> 历史版本的能力描述、包体积、测试数字以 [CHANGELOG](CHANGELOG.md) 对应条目为准；
> 本文不保留会过期的计数。

## 五、不在当前范围内的事

- iOS 安装包；云端账号、云存档、作品分发平台。
- 可视化时间轴 / 节点编辑器；实时联机。
- 通用游戏引擎级物理、3D、动画骨骼系统。

### 两端表现差异（设计意图待定）

有几条手机端与桌面端口径不同（CG 铺满还是留边、`@fg` 整屏蒙版还是贴坐标、横屏半身裁切是否刻意、
选项宽度是否随屏、CG 是否进存档持久化），**既不判为 bug，也不写成已支持**，等设计意图敲定再统一；
明细与现状口径见 [手机端编游戏](手机端编游戏.md) 的能力边界一节。

## 六、评价一个版本时看什么

- 剧本能否在手机上写出来、在电脑上跑通、导出的成品能被陌生玩家打开。
- 改动不破坏既有工程与旧存档；测试全绿、门禁通过（见 [贡献指南](贡献指南.md)）。
- 新指令 / 新配置在文档里有对应条目，不出现文档与磁盘不一致。
