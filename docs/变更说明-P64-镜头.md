# P64 变更说明：镜头（@camera 上手机）+ 背景交叉淡入

## 1. 手机端一直没有镜头

`@camera` 在桌面端早就有四个子命令（zoom / pan / shake / reset），手机端一个都没有，全被丢进 `unsupported`。所以同一份剧本在电脑上是"推近一下、抖一抖"，在手机上是死板的静态画面。

这次补齐，语义严格对齐桌面 `engine/runtime.py`：

| 子命令 | 写法 | 手机端效果 | 是否进存档 |
| --- | --- | --- | --- |
| zoom | `@camera zoom 1.0 1.2` | 0.62 秒缓入缓出推近/拉远，围绕画面中心 | 是（终值存为 `cameraZoom`） |
| pan | `@camera pan 右 1.2` | 按秒数平移到一侧，位移 = 短边 14% | 否（瞬时演出） |
| shake | `@camera shake 0.8 26` | 按幅度抖动，尾巴自动衰减 | 否 |
| reset | `@camera reset 0.9` | 缩放和平移一起回到原位 | 是（回 1.0） |

两个实现细节值得说：

- **连续 zoom 不跳变**：补间起点用"当前实际缩放"，不是作者写的起始值。写 `zoom 1.0 1.2` 之后紧跟 `zoom 1.0 0.8`，画面不会突然弹回去。
- **镜头只作用于场景**：背景、立绘、CG 一起缩放平移；对话框和选项按钮不动（跟着动会晕）。
- **底图多铺一点**：平移/抖动会把画面推出画布。按当前偏移量动态放大底图（`sceneMargin()`），保证不露黑边，静止时不额外裁边。

## 2. 背景切换原来是硬切

`@bg` 换图是瞬间替换，多张背景的剧本看起来像幻灯片翻页。

现在所有背景切换默认带 **280ms 交叉淡入**：旧图先铺满，新图按进度盖上去。CG 切进/切出也走同一条管线。作者不用写任何额外指令。

## 3. 真机第一次跑通（附实测）

拿用户自己的 vivo V2323A（Android 16 / WebView 151 / 1080×2400）实测：

- vivo 浏览器打开 `file://` 单文件 → 正常，标题页、蓝色主按钮、中文字体都对
- 点「开始新故事」→ 进正文，米色背景 + 深色面板 + 旁白正确
- **发现**：浏览器自己那条顶部搜索栏 + 底部工具栏吃掉约 250px，所以裸 html 不是全屏沉浸——这是 APK 的存在理由

新增 `tools/android_probe.py`（一条命令一件：`info` / `browsers` / `open` / `tap` / `rot` / `shot` / `logcat` / `reverse`），后面每轮真机验收都用它。

## 验证

| 项 | 结果 |
| --- | --- |
| 内核 | `cameraZoom` 进存档、reset 回 1.0、pan/shake 不改持久值（vm-smoke 新增 1 组断言） |
| `unsupported` | 不再有 `camera`（`video`/`fg`/`anim` 仍在，如实标注） |
| 画面 | zoom 后画面明显推近、pan 后偏移保持、shake 期间抖动、reset 回正 |
| 淡入 | 红 → 中间混色 `[132,107,60]` → 纯绿，280ms |
| 门禁 | 全量 `1083 passed + 1 skipped` |

## 边界

- `@video` 仍未实现：真视频解码 + 帧率对齐不是小活，不做半成品。
- `@fg`（前景层）、`@anim`（立绘补间）、`@plug:shake` 仍未实现，会如实进 `unsupported`。
- 镜头没有"边推边抖"的并行轨（桌面有 Timeline，手机端是顺序执行）。
