这里只记**发版**：下载新版的人能感觉到什么变了。

内部迭代过程（试错、推翻重来、踩过的坑）不在这里 —— 那是给我们自己看的，
不随仓库分发。正文若出现 `P` 号，那是内部编号，**仅作追溯用**，不构成对外版本线；
对外只有真正发版才动 `v` 号。见 [版本规则](版本规则.md)。

## 2026-11-19 · v1.2.1 · 视频真能放了，作品也能发给别人

**这一版三件事：一段真视频能进作品，成品能发给别人，平板横屏真的排成三栏。**

**一、真视频进「幕」。**
以前 `@video` 只能放一串连号图片，等于"看起来像视频的幻灯片"。现在手机相册里选一段真视频
（`@video 名 file`），原样进素材库，不压不转码；单文件上限 24 MB，超了会告诉你先在手机里剪短。
播放器同时只解一个视频：切幕、换背景、读档、退出立刻停、清、放；内存或核数不够的手机
自动静音并把绘制边长压到短边 ≤720；实在解不动就画一张兜底画面并说明，不黑屏、不卡住推进。
旧写法 `@video 名 fps=` 一个字节没坏，老作品打开还是原样。

**二、作品能发给别人，也能接别人的。**
安卓壳之前只会开自己包里的东西。现在作品可以直接分享出去（微信、QQ、文件管理器都认），
别人发来的 `.gal` 点一下就能打开——不用先开 App 再找"导入"。

**三、平板横屏排成三栏。**
横屏大屏以前是把手机那套放大：立绘撑满、选项拉成一条横贯全屏的带子。
现在人物在右、台词和选项在左，各自有边界，1280×800 与 1024×600 都不重叠不出界。

**四、手机上不再「满屏都是框」。**
上一版基本是照着桌面端缩，手机上一眼看过去：台词行挤出屏幕右边、新手大卡片盖住预览、
横屏预览框撑满整屏、首页底部一个能点的地方都没有。这一版按真机截图逐条修——
台词行拆两行（下拉和删除在第一行、台词框独占第二行）；首页加底部四格导航
（作品 / 新建 / 导入 / 设置），横屏时转成左侧竖条；新手卡不再首次自动弹，
要引导走「帮助 → 新手引导」；横屏预览框限高 168px；设置抽屉之前被自己的遮罩盖住、
里面每一项都点不动，现在能点；设置里多了一项「预览比例」（16:9 / 20:9 / 4:3），
只改那块预览框的形状，不动导出结果。

**修掉的真问题：**
- **设置里每一项都点不动**：抽屉和遮罩都没设层级，点击落在遮罩上，只有"点外面关闭"能用。
- **背景名在、图片不在时，预览框说"选背景后这里显示画面预览"**：明明已经选了，缺的是文件。
  现在明说「背景「xxx」找不到文件」，并提示名字对不上或图还没导入——不然人只会反复点那个下拉框。
- **首页中间那块纯黑**：只有一个作品时，卡片下面到动作区之间空着小半屏。
  现在唯一的那张卡自己长高吃掉它，横屏矮屏单独回退成定高，不会穿到导航底下。
- 桌面端换背景时 CG 不退场，两张图叠在一起。
- 转屏后视频进度错乱：时间轴没跟着重置。
- 坏备份导入会先报"已导入"、再把你清空——现在明确报错，不吞。
- 另四处点了没反应、也不报错的静默失败。

- **体积提示真的能到你眼前**：40 MB / 80 MB 的提示以前被接口吞掉了，作者根本看不见，现在看得到。
- **从别的 App 分享进来**：相册里选视频 / 图片分享到 MYONL，先进收件箱，回到编辑器再搬进素材库。

**五、首页少了一课。**
首页原来摆着「三步上手」，编辑器菜单里本来就有「帮助 → 新手引导」，同一套教程说两遍。
删掉了，首页回到只有作品和三个动作。空列表新人的引导走菜单，那里一步不少。

验收：全量 `1395 passed, 3 skipped`（退出码 0，本地实测 156–162s）；
APK `2,213,701 字节`（较 v1.2.0 增加 9,304 字节 / +0.42%）；安卓壳首次编译通过、签名校验通过。

已知上限：
- 单文件 HTML 仍把素材内联成 base64，素材总量到几十 MB 就不好开了。
- 手动构建的测试包版本代码用的是运行号，比正式版小，不能覆盖安装——测试包只能先卸载再装。

## 2026-11-19 · v1.2.0 · 装上有东西可玩，点按钮真有反应

**这一版三件事：一个装了很久没人发现的哑弹，一个白占体积的示例，一处「编辑器认、引擎不认」的格式。**

**一、APK 里所有「确认 / 取消」弹窗都是哑的。**
安卓外壳从一开始就少装了一个组件，浏览器里那种确认框在包里根本不弹 ——
不弹、不报错、直接当作你点了「取消」。最要命的一处是导入备份：
点「导入」会先问「会覆盖本机进度，确定吗」，那一问从来没出现过，
所以导入永远是静默失败。现在确认框真的会弹出来，确定和取消都真的算数；
页面加载不出来也会明确告诉你，不再是黑屏。

**二、装上打开只有空书架，其实包里带了示例。**
每次构建都往包里塞了一个约 547 KB 的示例游戏，注释写着「装上就能直接玩一关」，
但首页从来没有这个按钮 —— 那 547 KB 一直白占着。现在首页「开始新的」里多一项
「试玩示例」，包里带了才显示，点进去就能玩。

**三、编辑器能收 webp / jpeg，引擎不认。**
导入图片时这四种格式都收，可是运行和打包只找 .png / .jpg。
你拖一张 webp 进去，编辑器里看得见、能摆位置、能预览，
等到打包或运行才报「缺素材」。现在四种都认，大图也会一起压小。

- **竖屏的选项变成了一整块底板**：以前「谁在说 / 说什么 / 能选什么」是三块分开漂在角色
  身上的东西，读起来要来回找；现在底部一张板，名字、问话、选项从上到下一列排好。
  横屏没动，人物在右、选项在左本来就是横屏的标准摆法。
- 长游戏不会越玩越占越多：解出来的图约 1 秒扫一次，超过 160 MB 就从最久没画到的开始放掉，
  当前画面在用的绝不动。低端机上玩到后半段被系统杀掉的情况会少很多。
- 存档写盘改成先写临时文件再替换，写到一半断电/杀进程不会留下一个半截的档；
  主档坏了会自动退到上一次的备份。
- 平板上横屏立绘不再撑满整屏，选项不再拉成一条横贯全屏的带子；平板竖屏的选项也收了宽。
- 选项出现时角色名不再跟着对话框一起消失（之前是一片没主语的问话浮在立绘腿上）。
- 换手机导入备份，有哪几项因为存储满了没写进去，现在会明确报出来，不再报「已导入」然后刷新。

验收：全量 `1278 passed, 3 skipped`（退出码 0，本地实测 113.72s）。
真 Chromium 四档截图（手机竖/横、平板竖/横）走完首设→标题→游戏内台词，均读到目标状态。

已知上限：
- 单文件 HTML 仍把素材内联成 base64，素材总量到几十 MB 就不好开了；更大的要走「文件夹 / zip 发行」，还没做。
- 真视频通道（`@video 名 file`）在编辑器与备份链路已接；APK 内置示例不含视频素材，作者作品里的真视频随单文件成品导出。

## 2026-11-18 · v1.1.1 · 存档真的存得下来，老手机也点得开

**这一版只说一件事：v1.1.0 里两个「看着正常、实际坏事」的地方修掉了。**

**一、存档导出是假成功。**
v1.1.0 的存到手机上，点了会弹「已导出到下载目录」—— 但包在安卓里根本没有那个目录，
文件一个字节都没写出来。换手机的时候你会以为备份过了，恢复出来才发现全空。
现在它真的调起系统的「保存到」，你选位置，文件就落在那儿；拦下来的时候会明说被拦了，
不再报假成功。

**二、包不大，但一进去还是白屏。**
打开时会把所有图**一次性同时解压**。图的总量前一版已经管住了，可「同时解」这一下
的瞬时占用是稳态的好几倍 —— 内存小一点的手机点进去就是白屏。现在改成一批一批解，
封面排最前面，先出画面再慢慢铺。

- 顺带：素材很多时打包器会把长边降下来（1600 → 1280 → 1024），降到手机扛得住为止。
  真降到过的话，打包结束会告诉你降到了哪一档，不闷着。
- 顺带：手机竖着拿和横着拿，能自动挑`_p` 竖版变体；没做竖版图就回退主图，不会空。

验收：全量 `1235 passed, 3 skipped`（退出码 0）。

## 2026-11-18 · v1.1.0 · 备份能连素材一起带走

**这一版只说一件事：换手机时，作品不会只剩一堆找不着图的剧本。**

以前点「拿出全部作品」导出的是一份 JSON，里面**只有剧本** —— 素材存在另一个地方
（IndexedDB），根本没跟着走。用的人会以为备份过了，换机恢复出来才发现图全丢了，
比没备份更伤人。

- **备份带素材**：导出的 JSON 现在连图片、音乐一起打包，恢复时**按原名铺回去**，
  剧本里的 `@bg 教室` 还是指向 `教室`，不会变成 `教室-2`。
- **导入等素材写完再刷新**：以前导入完立刻刷新，素材还在一个个铺 —— 恢复一半。
  现在等它铺完。
- **示例工程换成自己做的素材**：`games/newbie_demo` 的背景和立绘是这次用 AI 生成的，
  首次打开就是真画面（以前是几 KB 的纯色块）。目的只有一个：**证明素材能上传、能显示**。
- **仓库不再带别人的作品**：一部短篇和一套示例游戏移出仓库，不再随仓库分发。
  `moonlight` 模板一并下线 —— 它原来是整套复制别人的示例游戏，拿它当「新建游戏」的底子
  等于替别人分发素材。现在传 `--template moonlight` 会明确报错并说明原因。

验收：全量 `1220 passed, 3 skipped`（退出码 0）；备份链路实测 **14/14**（真 Chromium：
导出后清空 localStorage + sessionStorage + IndexedDB 模拟换手机，再导入 —— 剧本回来、
图片回来、音频回来、名字原样、类型对、两边都能读到）。

已知上限：备份是 JSON + base64，体积约等于成品（素材越大文件越大）。超大素材仍要等
「文件夹 / zip 发行」，那是下一版的事。

## 2026-11-18 · v1.0.1 · 素材投递区 + 音频进成品 + 从别的 App 分享进来

v1.0.0 只解决「图能进来」，进来之后还得会选文件、会放音乐、会从别处弄素材。
这版把素材入口做完整：

- **投递区**：素材页顶上是一个虚线框，写着「把文件放进来」。手机上点一下弹文件选择，
  桌面上直接把文件拖进去（拖进来时框会亮）。收什么、压多大、多大算超，全写在框里 ——
  不用去猜规则。
- **音频进成品**：mp3 / ogg / m4a 原样存，导出时进 `pack.audio`，播放器的 BGM / 音效 /
  语音三条线本来就读它，接上就能响。
- **守住边界**：单个 24 MB、一次 20 个。超了明确说超了，不静默丢。
  txt / 视频这类成品里用不上的，直接拒收。
- **从别的 App 分享进来**：安卓壳注册了 `SEND` / `SEND_MULTIPLE`，在相册选完图点
  「分享 → MYONL」就进素材库。手机分屏把文件拖进 WebView 做不到（WebView 不接系统级拖放），
  分享是安卓上那条人人都有的路。
- 顺带修：多选里混进一个不能收的文件，进度条会永远卡在「导入中」。

验收（真 Chromium）：11/11。含「wav 存进 IndexedDB 且标成 audio」「拖拽能收」
「超 20 个给提示」「txt 被拒」。

## 2026-11-18 · v1.0.0 · 手机上终于能出带画面的作品

在这之前，手机上做出来的东西**永远是「纯文字 + 蓝渐变底」**：素材页是空的，
导出时素材写死成空对象。等于能跑，但没有画面。

- **素材放在 IndexedDB**，不塞 localStorage。后者总共 5 MB 出头，手机拍的一张图转
  base64 就三四兆，两张就把作品库挤坏。名字索引另存一份，好让接口同步答得上来。
- **选进来就压**：最长边 1280、jpg 0.82。手机原图直接塞进作品，导出的 HTML 会变成
  几十兆，发给谁都打不开。
- **素材页给了真入口**：从相册选图 → 导入进度 → 列表立刻刷出来。
- **缩略图补齐**：图片走浏览器自己的取图通道，绕不过请求劫持，不补就是一排空框。
- **导出带上素材**：成品里就是真画面，导完会提示「带了 N 张图，约 X MB」。
- 顺带修：素材面板层级只有 80，被场景详情页盖住，手机上点「素材」看起来像没反应。

验收（真 Chromium + 本地 HTTP 模拟 APK 环境）：9/9，含「缩略图真的画出像素」
和「成品里 `@bg` 指向的图确实在包里」。
