## 2026-11-18（P107：第一次打开先问三件事）

以前第一次打开作品，直接一张「怎么玩」卡砸在剧情上：三条说明压着台词，看完才让开始，
而且**画面方向、台词排法都得自己进菜单里找**。现在改成开局前的三屏向导，一屏只问一件事：

1. **用哪种画面？**（自动 / 竖屏 / 横屏）—— 拿不准就自动，转手机时自己换。
2. **台词怎么排？**（幕 / 经典 / 字幕）—— 只是换个样子，剧情不受影响。
3. **怎么玩** —— 原来那张引导卡并进来，讲轻点 / 长按 / 选项三个动作，不再重复弹第二次。

底部永远有一个很轻的「跳过」，不想配的人一按就进游戏，不挡路；右上三个点告诉人"还有几屏"。

顺手补的两个坑：
- `setupDone` 落盘（`myonl:v2:prefs`），**问过就不再拦人**；老玩家（已看过引导）不弹。
- 向导吃掉了标题页那次点击，`tryFullscreen()` 就补在收尾那一下 —— 第一次玩的人最需要全屏，
  手机浏览器工具栏会吃掉一截画面。

验收：`_tools/tmp/setup_e2e.py` 走完「首启弹出 → 选竖屏+字幕 → 开始 → 进游戏 → 刷新不再弹 → 横屏再来一遍」，
失败项：无。契约在 `tests/test_p107_setup_wizard.py`（5 条）。

## 2026-11-18（P106：旧包不再堆在 Releases 上）

Releases 页面是玩家真正看"要下哪个"的地方，apk-1 到 apk-N 一路堆上去，没人分得清哪个是最新、
哪个是坏包。而 GitHub 插件没有删 Release 的能力、本机也没有 gh CLI —— 所以**造一个**：

1. `tools/gh_release_clean.py`：只用标准库打 REST，`--list` 只读列举（不需要 token），
   `--prune --keep 5 --yes` 真删。按 **tag 数字**倒序（`apk-10` 排在 `apk-9` 前面，
   字符串排序会排反），至少留一个，删 Release 时连 tag 一起删（`--cleanup-tag`），
   默认 dry-run，没有 `--yes` 一个字都不动。
2. CI（`.github/workflows/android-apk.yml`）发完新包**自己清一次**，只留最近 5 个；
   这一步 `continue-on-error: true` —— 清理失败不能把已经发好的包判红。
3. `tests/test_p106_release_hygiene.py` 盯住四件事：脚本按数字排序、默认不动手、
   CI 带 `--cleanup-tag` 且容错、README 的下载入口 tag 与文件名对得上。

两类历史包各自按数量收敛：安卓包留 3 个（`apk-14 / 13 / 12`，都是存档修好之后的），
Windows 发行候选留 1 个（更早的 rc6 已是 11 月初的代码，留着只会让人装错）。
`--list` 与 `--dry-run` 都不用 token —— 人在没有权限时也能先看清"会删谁"。

## 2026-11-18（P105b：换版本不丢档）

存档键 = `myonl:v2:save:<标题哈希>-<剧本哈希>`，而剧本哈希里带着剧本内容。作者发新版改一句台词，
指纹就变 —— 玩家的档还在盘上，界面里却"没有了"，体验上就是丢档。现在首次读档时扫一遍
localStorage：同标题（同一部作品）的旧指纹记录里挑最近的一份搬进当前指纹，**旧键不删**
（包更新出问题还能退回旧版本的档）。

踩到并修掉的坑：这个迁移函数被写成同名两份，后定义的那份**静默覆盖**了前面那份，迁移逻辑一直
没被执行（调试时连日志数组都没建立，看起来像"函数没跑"）。改名 `storeMigrateGid` 接进
`storeRead` 的首次迁移链（先散装旧键 `storeMigrate`，再指纹维度），并加契约测试守住
"同名函数只能有一份"。

## 2026-11-18（P105：存档真的能读回来了 —— 三个硬 bug）

这一轮把"存档"从"界面上有"变成"能读回来"。端到端验收（存 → 刷新 → 读 → 导出码 → 清空 → 导入 → 再读 →
继续游戏）第一次跑就把三个一直存在、但没人发现的问题照出来了：

1. **读档一律回到剧本第一句。** `myonl-core.js` 的 `save()` 写的是 `pc: state.pc`，而 `state.pc` 从来没有
   被维护过，永远是 `undefined` —— `JSON.stringify` 直接把 pc 丢掉，`load()` 拿到 0。所以"读档"从来没
   真的读到存档点，一直是从头开始，只是背景和立绘对得上，看不出来。改成存 `frame.pc - 1`（回到存档
   当时显示的那一句，而不是跳到下一句）。
2. **读档后是一张空画面。** 存档点后面紧跟 `@wait` 时，`loadSlot` 只 `next()` 一次就停在那儿，台词区是
   空的。现在把剩余等待抹平、继续走到出现台词为止（`settleAfterLoad()`），实在走不到（作者结尾只放了
   `@end`）就把存档那句补上。
3. **标题页的「继续游戏」永远不出现。** `hasSave` 读的是旧版单键 `saveKey()` —— 而且这个函数根本不存在，
   调用抛 `ReferenceError` 被 `try` 吞掉，`hasSave` 恒为 false。存档早在 P85 就搬到了
   `myonl:v2:save:<作品指纹>`。现在按新结构判断（有自动档或任意一格手动档）。
   顺带：自动档被清掉（清空后导入、换设备）时点「继续游戏」，原来会**从第一句重开**，玩家以为继续了。
   现在退到最近一格手动档。

另外两处体验修正：
- `@wait` / 章节卡期间，菜单键与右侧「存 / 回 / 设」原来点不动（被"不响应翻页"那条拦在前面）——
  玩家等得不耐烦想存个档，点了没反应只会以为卡死。界面入口一律提前判断，拦的只是翻页。
- 存档格记下说话人（`char`），读档补字时名字也在。

验收与门禁：`_tools/tmp/save_e2e.py`（两格存不同位置各读回、导出码→清空→导入码、继续游戏、非法/空
码、空档位、系统文件选择器），全绿；`web/test/vm-smoke.js` 增加"存读同一句"（核心层，node 直接跑）；
`tests/test_p105_save_reload.py` 6 条源码契约。全量 1174 passed + 1 skipped。

## 2026-11-18（P101：对话框不再挡画面 / 菜单不再把屏幕关掉 / 三档对话框可选）

用户的原话是「完全的车挡画面确实也不好」——这句话指的不是透明度，是**形状**。查下来是三处：

1. **对话框贴满左右、底部压到 0.97**（`drawPanel` / `panelFill` / `panelRect`）。竖屏 390 宽时面板占满整行，
   最底那条几乎是实色，立绘的鞋和地板彻底看不见 —— 画面被切掉一块再贴一张黑纸。
   现在设置里多一组「对话框」（`PREF.dlg`）：**经典** = 仍走不透明底板 + 九宫格皮肤（老玩家手感）；
   **幕**（默认）= 全宽暗幕，从 46% 屏高开始分三级压到 0.86，画面 46% 以上一点不动；
   **字幕** = 同样无框，最底只压 0.55。1/2 两档**不画矩形** —— 半透明矩形真正的毛病不是透明度，
   是它有一条边界：背景亮的地方露边、暗的地方消失，同一块面板在画面里时隐时现。
2. **面板高度按句子的实际行数给**（`panelTargetH`）。原来是竖屏 `rows + 0.9`、横屏写死 1.1 行，
   一句单行台词也撑出将近三行高的面板，底下那一整块是空的 —— 白占画面。现在竖屏 `max(1.4, rows)`、
   横屏 `max(1, rows)`，高度补间（`updatePanelH`）不变，切句时是滑而不是跳。
3. **菜单 / 存档 / 设置 / 回顾的遮罩从 0.93 降到「上 0.28 下 0.66」的渐变**（`drawMenu`）。
   原来打开菜单 = 把画面关掉，回来还要重新认这是哪一幕；面板底也从 0.98 收到 0.90、投影收一档。
4. 顺带：`textLeft(rect)` 统一正文左缘。内缩后正文仍在 `L.textW` 的宽（换行宽度是 layout 的契约，
   不能跟着面板缩），所以左右留白按面板居中算，不再一宽一窄。设置页多了第 7 组，横屏两列
   变成 4+3 组。

验证：`_tools/tmp/compare_dlg.py` 在手机竖横、安卓平板竖横四档各拍三张（`audit/dlg-{p,l,tp,tl}-{0,1,2}.png`），

## 2026-11-18（P100：`@video` 帧池 / 存档格文字收边 / README 换门面）

两件事都是"在桌面上看不出来、到手机平板上才炸"的。

1. **`@video` 帧缓存原来没有上限**（`myonl-player.js`）。`videoCache` 是个裸对象，按 `名#帧号` 往里塞，
   循环跑一轮就把整个序列全缓存下来 —— **一帧 1080×1920 解码后 8 MB 出头，10 秒 24fps 是 240 帧**，
   第一轮走完就是 2 GB 级占用，手机上表现为玩一会儿白屏。改成只留「最近用过的 14 帧」
   （`VIDEO_KEEP`，覆盖约半秒、够回头兜底），超出从最旧的开始丢引用交给 GC。
2. **进入预热 + 切走释放**。`@video` 事件里 `warmVideo()` 先把头三帧叫醒 —— 否则第一帧还在读，
   画面会黑一下才出图；`@bg` 接管时 `dropVideoCache()` 整片释放。播放时还会顺手把下一帧叫起来，
   帧率才跟得上。读档续上视频必须重设 `t0`：存档里那个时间戳是上次玩的时间，拿来算帧号会跳到随机帧上。
3. **存档格台词按真实内宽收边**（`drawSlotCard`）。原来是 `String(d.say).slice(0, 16)` —— 按字数截。
   竖屏两列够宽看不出来，横屏三列卡片窄，16 个中文字会**横着压到隔壁格子**上（P100 拍 README 截图时
   在横屏存档页一眼看到）。新增 `ellipsisTo(s, avail)`：用 `measureText` 一档档砍到放得下再补「…」，
   时间戳也走同一条路。
4. **README 重写**（中英两份）。旧版还挂着 rc15 徽章、1021 项测试、「最近四期」停在 P83、
   界面图全是桌面截图、"支持 Mac/Linux 吗 → 只 Windows"、"能做手游吗 → 不做"。现在：
   APK 下载入口在最上面、测试数改 1148、最近四期换成 P97–P100、"界面"换成手机竖横 +
   安卓平板竖横 + 视频背景五张真机图（`docs/images/m-*.jpg`、`t-*.jpg`、`l-save.jpg`）、
   FAQ 里把"玩家侧不限 Windows"和"平板不用单独打包""升级不毁存档"写清楚。

验证：新增 `tests/test_p100_video_pool_and_slots.py` 六条源码契约（帧池有上限 / 进入预热 /
切走释放 / 读档重设时钟 / 没序列不黑屏 / README 数字与图没飘）；`_tools/tmp/verify_video.py`

## 2026-11-17（P99：安卓平板适配 —— 钉死"物理字号"和"正文宽度"）

玩家侧只维护「手机 + 安卓平板」两条（同一份 H5 → 网页包 / APK）。平板不是"更大的手机"，
把它当手机放大会同时坏两个地方。

1. **字号从"逻辑比例"改成"物理反推"**（`myonl-layout.js`）。原来是 `fs = 短边/22`，
   而逻辑画布短边恒 1080 —— 等于字号只跟逻辑画布挂钩。手机 390 CSS 宽时 49 逻辑 ≈ 17.7 CSS px
   刚好，平板 768~800 CSS 宽时缩放系数是 0.71（手机 0.36），同样 49 逻辑就成了 **34.8 CSS px**：
   整屏内容被放大近一倍，这才是"平板没适配"的真身。现在按目标物理字号反推
   `fs = 18.5 × 1080 / 短边CSS`，手机 51 / 平板 25 / 大平板 17，落到眼睛里的字一样大。

## 2026-11-17（P96：安卓壳真的出了 APK，且能覆盖安装）

想要的东西很简单：一个能装进手机的包，装完不会白屏，下次更新不用卸载。
上一版走的是 Capacitor + `assembleDebug` —— 它能编，但编出来的是 **debug 签名**，
CI 每次给机器新生成的 debug key 都不一样，所以新包装不上旧包，玩家只能先卸载，

换成自建 WebView 壳（`android/`，Groovy Gradle，不依赖 node）：

- **origin 固定**：`WebViewAssetLoader` 把 assets 挂到 `https://appassets.androidplatform.net`。
  不用 `file://`，因为 `file://` 下 localStorage 不保证持久 —— 换个壳就丢档；

- **沉浸全屏 + 转屏不重建**：`windowFullscreen` + `WindowInsetsController.hide(systemBars)`，
  `configChanges` 补全（否则一转屏 WebView 重载、剧本回到标题页）；
- **返回键接管**：`window.myonlBack`（播放器新增）—— 面板开着就关、游戏里就开菜单、
  都不是才 `finish()`；
- **不申 INTERNET**：素材全内嵌，不需要联网。

第一次编出来的包：**`MYONL-apk-3.apk` 3,770,281 B / 107 个条目**，APK Signing Block
4,088 B（v2/v3 已签名），里面 `assets/index.html` 3,110,702 B。已验证：解出来的 HTML

## 2026-11-16（P74：手机连电脑 / 插线互传 / AI 预留 / 全身立绘）

**事情的原样**：编辑器本来就是跑在电脑上的 HTTP 服务，手机是它的浏览器客户端 —— 手机打开同一地址就在改电脑上那份工程，协同不缺机制，缺的是「手机怎么找到地址」。

**手机连接（不用线）**：`engine/mobile_link.py` 探测局域网 IPv4（UDP connect 试探出口，过滤 127.*），用 `segno` 把地址画成浅底深码的 PNG data URI，编辑器新增 `GET /api/mobile-link`。设置中心里一张卡片：二维码 + 地址 + 复制 + 重新探测。本机实测 `http://10.20.152.240:8790/`。

**插线推成品**：`adb_state()` / `adb_push()` 找 `MYONL_ADB` 或 `_tools/platform-tools/adb.exe`，`adb devices` 带 12s 超时、`TEMP` 指到同级目录（默认 `%TEMP%` 会被拒），推前先 `shell mkdir -p /sdcard/Download/MYONL`。**没设备就如实报「插好后打开 USB 调试」，不假装成功**。

**AI 预留**：配置落在 `~/.myonl/ai.json`（用户目录，不进工程 / 导出包 / git）。`payload()` 只回掩码，任何情况下不回明文；空 key = 沿用旧值，`clear_key:true` 才清；`base_url` 必须 http(s)，数值夹紧；写盘 tmp + `os.replace` + 尽力 `chmod 600`；`ping()` 只打 `/models`，不烧 token。失败一律 HTTP 200 + `ok:false`（「还没配好」不是接口错误）。

**全身立绘 + 常驻微动**：竖屏脚底改贴「对话框上沿」（`panelY - 6`）、身高上限 `min(0.86 屏高, panelY-6)` —— 之前贴屏幕底边，下半身被面板盖住，等于又变回半身；横屏仍贴底边保持人够大。`idleMotion()` 加 ±1.1% 呼吸 + ±0.9% 微摆，以脚底中心为锚先落点再 rotate 再 scale，相位按槽位错开。**这不是 Cubism Live2D**：那要 `.moc3` + 专有许可 SDK + 美术绑骨骼，MIT 引擎内置有法律问题；要做的是分层立绘（body / eyes_open / eyes_closed / mouth_*）驱动眨眼口型，需要作者自己出分层素材。示例立绘换成全身图（368×1400 / 382×1400，按 alpha 包围盒裁贴边）。

**顺手修**：手机上 `.center-page.split` 的 `left:auto; width:56%` 特异性高于全屏规则 → 设置中心只在右侧占三分之二、左边一片空白（窄屏强制整屏）；`.set-tabs` 固定 132px 竖列吃掉三分之一屏宽（窄屏改顶部横排）；19 处 `var(--yellow)` + 3 处 `var(--peach)` 全是提示/徽标/选中框语义 → 换冷色（黄→天空蓝、橙→紫），红色只留给真错误。

**测试**：`tests/test_p74_mobile_link.py` 13 条（`[pytest.mark.unit]`，进门禁）。注意 `pytestmark` 必须是**列表**，单值会被门禁判为漏声明；本机续跑全套要 `OPENBLAS_NUM_THREADS=1`，否则 6% 处 `OpenBLAS memory allocation` 直接中断。全套 **1105 passed / 1 skipped**，pyright 112 = 基线。

**验证**：临时工程带 `@music`+`@sfx` → `MYONL_DEBUG.audio` 显示在播、点喇叭 `muted=true`；小图 `saved==0` 仍走 PNG；缺音频进 `missing` 不抛异常。新增 5 条 pytest + vm-smoke 的 music/sfx/存档断言，全量 `1082 passed + 1 skipped`。教程示例单文件 83 KB，`unsupported` 空。版本升 rc9，PyInstaller 打进 157 个 PIL 模块（exe 里压缩也可用）。

## 2026-11-15（对话框皮肤：一张图自适应 + 画布可视化 + 反导出成品）

**为什么不是「贴一张 textbox.png」**：主流教程（Ren'Py + Photopea）的做法是固定尺寸 PNG 整张替换，面板尺寸或分辨率一变就变形。MYONL 改为「一张 PNG 按九宫格切片自适应」：四角不缩放、边与中段拉伸，渐变蒙版与图案填充由引擎计算（不用回 PS 重做），编辑器里可直接在画布上拖位置/高度，最后还能把当前设计**导出成成品 `textbox.png`**（可当 `panel_image`，也能给别的引擎用）。
