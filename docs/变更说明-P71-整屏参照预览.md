# P71：UI 设计区「整屏参照预览」—— 调参数时能看见手机上会变成什么样

## 为什么做

用户原话：「你的这个 ui 设计应该有个缩略图可以参照运动去看」。

P70 把选项按钮的七项参数真正接通了（编辑器 → config.json → 播放器 → 单文件导出），但**调的时候没有任何参照物**：
改滑杆只看到右边的数字从 620 变 800，不知道这两个数字在手机上意味着什么。要改得好看，得先导一次、跑一次、看一眼 —— 这就是认知负担。

P71 加了一块 300×649 的整屏缩略图：按当前作品背景、当前参数、当前分组实时画「手机上的样子」，改哪个参数它当场动。

## 做了什么

### 1. 修一条根用错的 bug（这是整屏预览能取到背景图的前提）

`_get_asset` 取单个素材时用的是 `self.app.data_root`。但 `--script games\教程示例\script.gal` 启动时 `data_root` 是**仓库根**，而素材列表 `_get_assets` 用的是**剧本所在目录**。
结果：列表里有 `bg001`，点开 `/api/asset/images/bg001` → 404。

新增 `_resolve_asset(category, name)`：先在 `_current_project_root()` 找，找不到再退回 `data_root`，`_get_asset` 两处调用全部换成它。
这与 P70 修的 `_ui_design_get/set` 是同一类错误 —— 素材按作品目录扫、取单个却按另一个根取。

### 2. 整屏缩略图（`editor/editor_uidesign.js`）

`STAGE = { W:300, H:649 }`，按 `BASE`（竖屏逻辑 1080×2338 的那套几何）等比缩放后画：

- 背景：`/api/assets` 里第一个名字以 `bg` 开头的图，`stageCover` 等比裁切铺满；
- 暗角 + 立绘占位（`spriteH:900`）；
- 对话框面板（`panelH:468`、底距 96）+ 名字牌 + 两行假台词条；
- 两个选项按钮（宽/高/间距/圆角/底色/文字色全部读当前参数）；
- 右下三颗快捷栏胶囊、右上两枚圆钮（静音/菜单）；
- 当前 tab 对应的那一组描一圈蓝框 `rgba(79,140,255,.95)` —— 看的是哪一组，框就框哪一块；
- 参数变化走 rAF 补间（170ms），从旧几何滑到新几何，变化的方向和幅度一眼能看出来。

### 3. 手机上让它「看得见」（`editor/editor.css`）

原来窄屏有一段 `.ui-design-preview { display: none !important; }`（P68f 为了不让 pygame 大图把参数列挤下去）——预览整块被藏了，所以缩略图插进去也是 0×0。

现在分三档：

| 场景 | 缩略图位置 | 尺寸 |
|---|---|---|
| 竖屏（≤860 宽） | 吸顶 sticky，表单在下方滚 | 158×342 |
| 横屏（≤520 高） | 右上浮窗 fixed（不挤参数列） | 88×190 |
| 桌面（宽屏） | 原预览列，300×649 | 300×649 |

竖屏时 `#uidPreviewWrap`（pygame 那张大图）继续隐藏，只留缩略图。

### 4. 点一下放大看细节（新增）

小窗只有 158 宽，文字是糊的（这本来就是"看形状"用的）。点一下缩略图 → 铺满整屏（`height: 80vh`），再点一下收起。
放大时把节点临时挂到 `document.body` —— 挂在原处会受弹窗容器的包含块限制，铺不满整屏（实测底部被 tabbar 挡住才发现）。

## 踩到的坑（写下来免得下次再踩）

1. **`.uid-stage` 这个名字已经被占用**：P58 的画布拖拽容器就是 `div#uidStage.uid-stage`，CSS 里 `display:none`，靠 `.on` 才显示。我第一版整屏预览用了同名 class → 插进去立刻被隐藏，诊断半天才看出来（`getComputedStyle` 打出 `d=none`）。改成 `.uid-preview-stage` 才对。
2. **补丁脚本按 `\n}` 找块尾会切错**：`editor.css` 里缩进写的是 `  }`，第一次匹配到的不是块尾，结果把整个文件复制了一份进去（2459 行变 4870 行）。截断后括号数校验 `1201/1201` 才确认修好。改 CSS 一律用精确字符串替换，不用结构推导。
3. **窄屏 `order` 在 block 容器里无效**：`.ui-design-body` 是 `display:block` 时 `order:-1` 不起作用，预览被排到表单后面（要滚到底才看得见）。改成 `display:flex; flex-direction:column` 才真正吸顶。
4. **`flex-wrap: wrap` 是全局开的**：横屏改成 `flex-direction: row` 后，`max-width: calc(100% - 132px)` 的表单 + 124px 的预览正好换行到下一屏（`top` 算出 1255），加 `flex-wrap: nowrap` 才并排。

## 验证

- 竖屏 390×844：canvas 158×342，`top` 稳定 210（滚动 520 后不变 → sticky 生效）；改 800/70/#33224a/30 后选项明显变宽、间距拉开、底色转紫。
- 横屏 844×390：canvas 88×190，`top` 97，不压 tabs、不压 tabbar。
- 点击放大 → `class="uid-preview-stage big"`，铺满整屏盖住 tabbar；再点收起正常。
- `pytest -m "not slow"` 1085 passed / 1 skipped；`vm-smoke` / `layout-smoke` 全过；`node --check` 通过。

## 已知边界

- 缩略图只画「对话 + 选项 + 快捷栏 + 右上圆钮」这一屏。菜单页、设置页、存档页没画 —— 那几组的参数（`menu`/`settings`/`slots`）改了之后缩略图不会变，只有蓝框会挪到对应位置。
- 背景图取的是作品目录里第一个 `bg*`，不是当前剧情用到的那张。
- 立绘是占位方块，不是真立绘（真立绘要读剧本解析当前说话人，代价大于收益）。
- 横屏 88 宽的文字基本看不清，这是刻意换来的"不挤参数列"，细节靠点开放大。
