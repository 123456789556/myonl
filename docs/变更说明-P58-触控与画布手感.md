# P58 变更说明：手机上能拖、能放大、少误触

## 为什么改

P57 把画布编辑做出来了，但默认按桌面鼠标的尺寸在调：手柄 12px、命中带 14px、画布只有容器那么宽。换到手机上就是三件事同时坏——

1. 编辑器三栏在 390px 宽下每栏只剩 ~100px，UI 设计页的预览列被压成一条缝（实测画布 200×113）。
2. 113px 高的画布里，对话框面板只占 30px 高，12px 的手柄比手指小一半，抓不住。
3. 播放器是 `pointerdown` 就推进，手指一滑想拖动/误触也会翻页。

## 编辑器侧（`editor/editor_uidesign.js` + `editor/editor.css`）

- **窄屏全屏**：`@media (max-width:860px)` 时 `.center-page` 变全屏覆盖（`position:fixed; 100vw/100dvh`），UI 设计页铺满整屏。实测竖屏画布从 200×113 变成 360×203。
- **画布缩放 1.0x–3.0x**
  - 顶部缩放条：`−` / `1.0x`（点击回 1x） / `＋`，步进 0.25。
  - 桌面 Ctrl/⌘ + 滚轮；触屏**双指捏合**（记录两指初始距离比，实时改倍率，松手结束）。
  - 1x 基准 = 滚动容器宽度，放大后画布超出可视区域，`.uid-stage-scroll` 支持触摸滚动（`-webkit-overflow-scrolling:touch`）。
  - 窗口 resize / 转屏后自动按新宽度重算。
- **触摸命中带**：`pointerdown` 时会看 `pointerType`，触摸用 22px 命中带（鼠标 14px），并且 `body.uid-touch` 下八个手柄视觉放大 1.6 倍（`transform: scale`，不影响定位只放大视觉和命中区）、绿点 1.7 倍、缩放按钮变 34px 高。
- **事件从 mouse 换到 pointer**：`pointerdown/pointermove/pointerup/pointercancel`，鼠标和手指走同一条代码路径。
- **修掉 flex 挤压**：`.preview-img-wrap` 改成纵向 `align-items:stretch`，滚动容器 `flex:1 1 auto; width:100%`——之前预览列里的滚动容器被当 flex item 按内容宽度收缩，量出来只有 208px。

## 播放器侧（`web/myonl-player.js` + `web/myonl-layout.js`）

- **点击判定改成「按下 → 抬起」**：位移 >12px 或按住 >1.2s 不算点击。滑动/长按不再翻页，快速连点仍然能推进（跳过对话的手感保留）。
- **选项按钮最小高度 120 逻辑 px**（原 96）：1080 短边下换算到 390 宽屏约 43 CSS px，接近 44pt 触摸推荐值。
- **正文字号**：短边 1080 下从 42 → 49 逻辑 px（`unit/22`），390 宽屏上约 17.7 CSS px，原来是 15。横竖屏仍一致（都按短边算）。

## 验证

| 项 | 结果 |
| --- | --- |
| 竖屏（390×844）画布 | 200×113 → **360×203** |
| 放大两档 | 360 → **540**（1.5x），选择框仍贴住面板（比例 0.972） |
| 触摸拖右边缘 | `panel_width 0（全宽）→ 1000` |
| 桌面 1.25x 拖右边缘 | `1056`，`offset_x -94`（对边钉住） |
| 播放器滑动 | 滑 120px → 不推进、无报错 |
| 选项按钮 | 截图实测约 43 CSS px 高 |

截图：`screenshots/p58-portrait-canvas.png`（竖屏 + 放大后的手柄）、`screenshots/p58-phone-choice.png`（手机选项页）。

## 边界（没做的）

- **只有 UI 设计页做了窄屏全屏**。编辑器主界面（三栏、章节大纲、剧本编辑、素材面板）在手机上仍然是挤的——那是 P59 的活，要把侧栏收成抽屉、工具条收成图标。
- 没有做双指平移（只有缩放 + 滚动），画布放大后靠滚动容器拖动。
- 播放器没有做安全区补偿（刘海/底部横条），现在靠 `bottom` 留白顶，矮屏上可能贴住手势条。
