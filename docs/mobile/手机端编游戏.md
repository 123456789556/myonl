# 手机端编游戏：能做什么、不能做什么

装一个 APK，打开就是编辑器。**不需要连电脑，不需要服务器，也不上传。**

> 本文只写手机上这条链路的真实边界。谁和这里说的不一样，以这里为准（README 其次）。
> 最后一次按代码核对：2026-11-23，v1.2.58。

## 能做

| 事情 | 说明 | 存在哪 |
|---|---|---|
| 新建作品 | 起个名直接开写，空白起手（不再塞示范台词） | localStorage 作品库 |
| 写剧本 | 手机键盘输入，`.gal` 语法，缩进、`@` 指令照常 | 同上 |
| 变量与条件 | 属性面板末尾一条虚线栏「变量与条件 · 加一条」：记一笔数（`@set 好感 += 1`）或条件跳到别的幕（`@if 好感 >= 3:` + 缩进 `@jump 结局`）。写进本幕 `@end` 之前，跳自己这一幕会被挡 | 同上 |
| 章节树 | 场景列表按 `@chapter` 折叠成树，整行 40 高可点，「(未分章)」只在真的有散幕时出现 | 同上 |
| 放图片 | 从相册选、从别的 App「分享」进来；原图不动，另存 240 边缩略图给列表用 | **IndexedDB**（不是 5 MB 的 localStorage） |
| 放音乐 | 音频原样存，进成品当 BGM / 音效 | IndexedDB |
| 视频（真文件） | 相册选、从别的 App 分享进来的真视频原样存（不压、不转码）；单文件 ≤24 MB；播放器同时只解一个视频，切幕 / 切背景立刻 pause、清 src；内存小的低端机自动**降级**（仍能播，画质让步） | IndexedDB |
| 出成品 | **本机直接把剧本 + 素材拼成一个自包含 `.html`** | `engine/parser.js` + `engine/pack.js` |
| 打 APK（限装好的 APK 里） | 用包内 `template.apk` 换掉作品本体、签名模块现签，出来的就是能装的 APK | 下载到系统「下载」 |
| 带走作品 | 导出 **`.myonl`**（剧本 + 用到的素材，一个文件，电脑端能直接导入）；`.gal` 是纯剧本文本，`.json` 是整个作品库。导入时 `v` 认不出会当场说「更新版本导出的」，不假装成功 | 系统「保存到」 |
| 导入 | 三张卡：粘贴内容 / 选文件（安卓走系统选择器，v1.2.52 起真的能选）/ 从网页版 html 取素材。同名不覆盖 | localStorage / IndexedDB |
| 删错能找回 | 作品卡「⋯」里有改名 / 导出 / 导入 / 复制一份 / 版本历史 / 删除；删掉的进垃圾箱留 30 天，能还原、也能彻底删 | `myonl:off:trash:v1` |
| 示范案例 = 教程 | 装上只有**一份「示范案例」**（三幕带分支，能玩能改）。底栏「素材」页底部「写法速查」展开就是教程，里面一颗「打开示范案例」直接跳进去 | localStorage 作品库 |

「出成品」走的是 `engine/parser.js` + `engine/pack.js`，和电脑端 `engine/parser.py` 逐字段一致
（`tools/pack_diff.py` 拿 `games/` 下全部工程对拍）。**手机上打出来的包和电脑上打出来的是同一个东西。**

## 不能做（这些还是电脑的活）

| 事情 | 为什么 |
|---|---|
| `@anim` `@plug` `@include` | 这 3 条手机端解析器没实现，**遇到会明确报错并指出是第几行**，不会静默吞掉。成品能不能演要分开看：`@anim` 能演（`myonl-core.js:274` 有补间、播放器逐参数取值），`@include` 能演（电脑端打包时已内联展开，成品里没有这条 op），`@plug` **两头都没有**（播放器没有插件实现，静默跳过）。 |
| 用 `@voice` `@cg` `@fg` `@camera` `@transition` | 不在这份「不能做」里了：v1.2.15 起手机端解析器已支持这 5 条，字段与 `engine/parser.py` 逐条对齐（对拍见 `tests/golden/at_rules.json`）。 |
| `@include` 引入别的文件 | 手机上的作品是**一份文本**，没有第二个文件可引 |
| 在浏览器里打 APK | `template.apk` 和签名模块只在**装好的 APK 内**（`assets/`），靠浏览器的网页版没有这两样。电脑端走 `tools/pack_apk.py`（要 JRE），或交给 GitHub Actions |
| 跑测试 | `pytest` 是 Python 套件，只在电脑上 |

手机端解析器认这些指令：`@character` `@bg` `@music` `@sfx` `@show` `@hide` `@wait`
`@chapter` `@label` `@jump` `@end` `@set` `@if` `@video` `@voice` `@cg` `@fg` `@camera`
`@transition`，外加选项块 `@choice:` 和没前缀的台词行。

## 视频在手机上的两种走法

`@video` 有两条通道，写法不同：

- **帧序列**（不写 `file`）：帧图放 `images/videos/名_001.png` 起连续编号，`@video 名 fps=24`。
  播放器只保留最近用过的少量帧，切走立刻释放，避免一长串帧把内存吃满。
- **真视频文件**（写 `file`）：`@video 名 file`，走 `<video>` 解码；可追加 `loop=0|1`、`mute`。
  整段成品同时只活一个 `<video>`，切幕 / 切背景 / 读档 / 退出立刻 pause、清 src、清掉解码句柄。
  句柄层释放可观测（计数回 0、`readyState=0`、已暂停）；**解码后的原生位图缓冲是否归还给系统，
  环境里没有原生内存 API，测不出**——不写成"内存已释放"。

## 实测表现与能力边界

> 下面数字来自桌面 Chromium 的 **CDP 模拟低端机**（覆写内存/核数 + CPU 降速 + 限速），
> **不是真机实测**，也不含真实 GPU 解码带宽与热节流；真机表现以设备为准。

**立绘落位（与桌面端对齐）**

- `@show` 的 `pos / scale / z / x / y / layers` 在手机端不再丢字段，落位与桌面端同源；
  存档读档后位置不复位。这是补修手机端丢字段的 bug，不是新指令。两端画布逐像素比对未在本轮实拍，
  一致性验证到字段层与存读档层。
- 横竖屏切换后，帧序列视频会按当前帧号重置进度基准（t0），不再跳到随机帧。

**平板横屏布局**

- 平板横屏给出对话 / 立绘 / 操作三栏分区，1280×800、1024×600 下栏位不重叠、不出界；
  竖屏与手机退回整幅堆叠，行为不变。
- 已知观察项：1024×600 窄横屏对话栏与立绘栏之间缝仅约 11px（逻辑坐标），不重叠但余量小。
- 常驻浮岛（菜单 / 喇叭 / 存档回顾设置）实测遮挡画面 1.21%–1.63%，低于 3% 阈值，本轮不做底板化。

**素材量下的帧率与首屏（CDP 模拟口径）**

| 条件 | 表现 |
|---|---|
| 桌面档，120 张素材 | 帧中位 ≈16.7ms（约 60fps） |
| 模拟低端 4×，20 张素材 | 帧中位 ≈100ms（约 10fps），已跌破流畅线 |
| 重度低端 6×，20 张素材 | 帧中位 ≈166ms（约 6fps） |
| 位图缓存 | 上限 160MB；素材到 60 张时缓存停在约 45 张 / 158MB，超出部分走 LRU 清扫、需要时再解码 |
| 首屏 TTI | 桌面空载 0.49s；低端 4× 空载 1.14s / 120 张 4.28s；6× 空载 1.59s |

**两端表现差异（待定，不属已支持也不属已修 bug）**

以下几条手机端与桌面端口径不同，设计意图尚未敲定，先保持现状：CG 铺满还是留边、
`@fg` 整屏蒙版还是贴坐标、横屏半身裁切是否刻意、选项宽度是否随屏、CG 是否进存档持久化。

## 成品怎么给别人

导出的 `<名字>.html` 是一个自包含文件：播放器、剧本、素材全在里面。

- 微信 / QQ 发过去，对方点开用浏览器打开就能玩（不用装东西、不用联网）；
- 自己留着，双击也能玩；
- 素材多到 40 MB 以上，导出时会当场提示体积和风险；超过 80 MB 会警告「低端机会明显卡」——
  想瘦就先缩图，不要在手机上硬塞几百 MB 的原图。

## 升级会不会把作品弄丢

不会。作品和素材在应用私有目录里，**签名固定**（`android/keystore/myonl-test.p12`），
覆盖安装是升级而不是换 App，存储不会被清。刻意不换签名就是为了这个——换签名等于逼所有人卸载重装，
卸载会连存档一起删。

保险做法：出成品前导一份 `.json` 作品库备份。那是纯数据，随你拷到哪。

### 备份里带哪些素材

现在的 `.json` 备份分三桶：**assets（图）/ audio（音频）/ movies（真视频）**，外加一份
**kinds 类型索引**；导入时按 movies → kinds → assets 优先级还原，视频回来仍是 video，不会被当图。

**旧备份救不回视频类型**：更早的两桶备份只有 assets + audio，当年视频被混在图桶里、类型没带走。
这种旧文件仍能导入，但里面的视频只能按图片还原——不是新备份的问题，是旧文件当年就丢了类型，
别指望换机后视频还能播。

## 一句话边界

手机上：**写、放图放音乐、出成品、打 APK、发出去。**
电脑上：**`@anim` / `@plug` / `@include` 三条指令、多文件剧本、跑测试**（`@plug` 连电脑端打出来的成品也不演，见上表）。
