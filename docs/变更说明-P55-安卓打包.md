# 变更说明 P55 · 安卓打包（Capacitor 壳 + GitHub Actions 出 APK）

日期：2026-11-16
沿 P54 的 H5 播放器之后，把「手机能玩」推进到「安卓能装」。

## 一句话结论

播放器一行没改。安卓这层是**壳**：把一个已经验收过的网页包原样塞进 Capacitor，
用 GitHub Actions 的机器编 APK。作者侧的动作仍然是「导出手机版」那一个按钮。

## 为什么用 Capacitor 而不是自己写 WebView

| 方案 | 代价 | 结论 |
|---|---|---|
| 自己写 WebView Activity | 要维护 Java/Kotlin、权限、生命周期、每次系统升级都要改 | 不做 |
| Cordova | 生态老、插件停更 | 不做 |
| **Capacitor 6** | 只需 `npm i` + `cap add android`，网页原样加载 | 采用 |
| TWA（Bubblewrap / PWA） | 需要网站有 HTTPS 域名 + 上架 Play 才顺，侧载体验差 | 留作后续 |

选择 Capacitor 的核心理由：**壳和内容解耦**。网页包（index.html + pack.json + 3 个 js + assets）
是唯一会被反复重编的东西；壳一年动一次，甚至不动。

## 组成

1. **`tools/build_android.py`** —— 脚手架生成器（纯 Python，无第三方依赖）

   ```
   py -3 tools\build_android.py --www dist\web\教程示例 --out android-app ^
       --app-name 教程示例 --app-id com.myonl.demo --install --build
   ```

   - `--scaffold-only`：只生成 `package.json` / `capacitor.config.json` / `www/`，不联网；
   - `--install`：`npm install` + `npx cap add android` + 打 Manifest 补丁 + `cap sync`；
   - `--build`：`gradlew assembleDebug`，产出 `android/app/build/outputs/apk/debug/app-debug.apk`；
   - appId 会被校验（必须像 `com.myonl.demo`），网页包缺 `index.html` / `pack.json` 直接报人话。

2. **Manifest 补丁**（横竖屏的**真正开关**在这里，不在 JS 里）

   - `android:screenOrientation="fullSensor"` —— 四个方向都跟传感器走，竖屏横屏都能转；
     不写 `portrait` 也不写 `landscape`，锁死任意一个就等于砍掉另一半需求。
   - `android:configChanges` 补上 `orientation|screenSize|keyboardHidden` —— 转屏时
     Activity 不重建，WebView 不重新加载，剧本不会被打回标题页。
   - 补丁是幂等的：跑两遍不会重复加。

3. **`.github/workflows/android-apk.yml`** —— GitHub Actions 出包

   - 手动触发（Actions → 安卓 APK → Run workflow），可填工程目录 / 应用名 / 包名；
   - 推 `v*` tag 自动跑一次示例工程；
   - 步骤：checkout → Python 3.12 → Node 20 → JDK 17 → Android SDK →
     `pip install pygame-ce` → `python -m engine.webpack` → `tools/build_android.py --install`
     → `./gradlew assembleDebug` → 上传 `myonl-debug-apk` artifact；
   - 最后一步 `grep screenOrientation` 把转屏设置打进日志，方便在 Actions 里核对。

## 手机端的实际行为（装上 APK 之后）

- 全屏 WebView 加载本地 `www/`，不联网、不需要服务器；
- 竖屏/横屏随手机转，转屏后画面重排、台词位置续上（P54 的 `rewrap` 逻辑在 WebView 里同样生效）；
- 触摸推进（`pointerdown`），和浏览器里点屏幕一样；
- 进度存在 WebView 的 localStorage 里（`myonl:auto:<标题>`），杀进程再开还在；
- 返回键是 Android 默认行为（退出到桌面），**没有**做「返回标题页」——见"没做的部分"。

## 验证到哪一步了（诚实清单）

| 环节 | 在哪验的 | 结果 |
|---|---|---|
| 网页包编译 | 本机 | 通过（P54 已验收） |
| 脚手架生成（scaffold-only） | 本机 | 通过，12 条 pytest 守着 |
| `npm install` + `cap add android` | **本机**（Node 22.23.2） | 通过，生成了 `android/`，`assets/public` 里 3 个 js + pack.json 都在 |
| Manifest 补丁 | 本机 | 通过：`screenOrientation="fullSensor"`、`configChanges` 含 orientation/screenSize |
| `gradlew assembleDebug` | **GitHub Actions（已跑通）** | run 43792023632 全绿，产物 `myonl-debug-apk` 3.24 MB |
| APK 真机安装、转屏、触摸 | **没验** | 没有设备；需要在你的手机上装一次 |
| Actions 工作流本身 | **已跑通** | 第一次 `android-actions/setup-android@v3` 在 ubuntu-latest 上失败，改用 runner 自带 SDK 后全绿（含"检查转屏设置"步骤） |

## 没做的部分（别当成 bug）

- 返回键回标题页（要接 Capacitor App 插件的 JS 侧监听，需要打包器，暂不做）；
- 沉浸式全屏 / 状态栏颜色 / 启动图（Capacitor 默认 SplashScreen 是白底，可后补）；
- 正式签名的 release APK（现在出的是 debug 包，能侧载，不能上架）；
- iOS（Capacitor 同一套可加 `ios/`，但需要 macOS 编译）；
- 微信/抖音小游戏封装（还是 P54 那条：现在只差给播放器加壳）。

## 用到它的最短路径

1. 编辑器 → 界面设计 → 「导出手机版」→ 得到 `dist/web/<工程名>/`；
2. 想把 APK 给朋友装：把仓库 push 到 GitHub → Actions 页选「安卓 APK」→ Run workflow
   （project 填 `games/教程示例` 或你的工程路径）→ 跑完下载 artifact 里的 `app-debug.apk`；
3. 自己有 JDK 17 + Android SDK 的话，本地一条命令也能出：
   `py -3 tools\build_android.py --www dist\web\教程示例 --out android-app --app-name 教程示例 --app-id com.myonl.demo --install --build`。
