# 发布纪律

一句话：**仓库只放「陌生人下载下来就能用、能看懂」的东西。拿不准的一律进 `myonl-publish`，别推上来再想。**

这条规矩是踩过坑立的 —— 原来的 `NOTICE` 里写着「月光漫步原作仅本地研究，不随本仓库分发」，
而那 75 个文件其实一直在仓库里。说了不做，比不写更糟。

## 三层，别混

| 层 | 在哪 | 放什么 | 判据 |
|---|---|---|---|
| **公开仓库** | GitHub `123456789556/myonl` | 引擎、编辑器、播放器、测试、文档、自己造的示例 | 陌生人 clone 下来能跑、能看懂 |
| **本地 publish** | `D:\娱乐工作区\玩具项目\myonl-publish` | 别人的作品和素材、半成品、个人试验 | 有版权疑问，或者还没成形 |
| **删掉** | —— | 试了几次就不用的 | 留着只会让人以为它有用 |

`myonl-publish` 不是垃圾桶，是**待定区**：以后想用还能用，只是不进公开仓库。

## 版权红线（最高优先级，任何理由都不破）

- **别人的游戏、别人的图、别人的音乐 —— 一律不进仓库，一次都不行。**
  「只放一个示例」「只是本地测试」都不是理由：推上去就是再分发。
- **MIT / 开源许可不等于随便放。** 许可要求保留版权声明和许可原文；塞进示例工程里
  很容易把声明弄丢，丢了就是违规。真要用，单独目录 + 完整 LICENSE 一起带。
- **NOTICE 里写了「不随仓库分发」的，就必须真的不在仓库里。** 文档和磁盘不一致，
  按项目规矩要当场改——这次改的是磁盘。

## 推之前问自己三句

1. **陌生人看到，会不会以为是我们的东西？** 会 → 别推。
2. **这个功能我自己用过三次吗？** 没有 → 放 publish 试，别拿仓库当试验田。
3. **推了之后，愿不愿意为它的每个 bug 负责？** 不愿意 → 别推。

## 现在各目录归哪层

| 目录 | 层 | 为什么 |
|---|---|---|
| `engine/` `editor/` `web/` `tests/` `docs/` | 公开 | 引擎本体，缺了就跑不起来 |
| `games/教程示例` `games/标准示例` `games/新游戏模板` | 公开 | 自己造的占位素材，改起来没有心理负担 |

| `android/` `brand/` `locale/` | 公开 | 自己的壳、自己的图标、自己的语言包 |
| `dist/` `build/` `saves/` `screenshots/` `.pytest_cache/` | **不入库** | 产物和本地状态，由 `.gitignore` 挡住 |
| `games/研修日志` | **publish** | 版权归原作者，只在本地做回归样本 |
| `作品/副产物/月光漫步` | **publish** | Ren'Py 的示例游戏，不是我们的东西 |

## 每次推之前跑一遍

```powershell
# 1. 有没有不该进库的东西混进来了（应为空）
git status --short

# 2. 有没有别人的作品躺在里面（应只出现自己造的示例）
git ls-files games 作品

# 3. 全量门禁（必须单独跑，别开两个）
$env:SDL_VIDEODRIVER="dummy"; $env:SDL_AUDIODRIVER="dummy"
py -3 -m pytest -q
```

三条都清白了才推。**推之前不看，等于让别人替我们踩雷。**
