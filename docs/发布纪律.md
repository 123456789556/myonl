# 发布纪律

一句话：**仓库只放「陌生人下载下来就能用、能看懂」的东西。拿不准的一律进 `myonl-publish`，别推上来再想。**

这条规矩是踩过坑立的。一次是 `NOTICE` 里写着「月光漫步原作仅本地研究，不随本仓库分发」，
而那 75 个文件其实一直在仓库里 —— 说了不做，比不写更糟。另一次更蠢：规矩写好了，
我却只把它写进文档，没照着做，`docs/` 里照样躺着 50 多个给自己的迭代记录。

## 三层，别混

| 层 | 在哪 | 放什么 | 判据 |
|---|---|---|---|
| **公开仓库** | GitHub `123456789556/myonl` | 引擎、编辑器、播放器、测试、给用户的文档、自己造的示例 | 陌生人 clone 下来能跑、能看懂 |
| **本地 publish** | `D:\娱乐工作区\玩具项目\myonl-publish` | 别人的作品素材、内部文档、半成品、个人试验 | 陌生人用不上，或者有版权疑问 |
| **删掉** | —— | 试了几次就不用的 | 留着只会让人以为它有用 |

`myonl-publish` 不是垃圾桶，是**待定区**：以后想用还能用，只是不进公开仓库。

## 文档也分两堆（这一条曾经搞错）

`docs/` 里原来有 50 多个文件，绝大部分是给自己的迭代记录 —— 陌生人点进来只看到一堆
`P53`、`P74`，他不知道那是啥，也不该知道。

现在按用途切开：

| 进公开仓库（陌生人要看） | 进 publish（自己要看） |
|---|---|
| `README.md` · `README.en.md` | `STATUS.md`（现在在哪、下一步做什么） |
| `CHANGELOG.md`（只记发版） | `ROADMAP.md` · `BACKLOG.md` |
| `engine_spec.md`（指令全集，写剧本必须查） | `计划/`（唯一计划页） |
| `快速上手.md` · `手机端编游戏.md` | `变更说明-P*.md`（逐条迭代记录，20 多篇） |
| `素材导入指南.md` · `打包使用指南.md` | `接手规矩.md` · `md-规范说明.md` |
| `存档与升级.md` · `版本规则.md` | `展示_60秒分镜与投稿包.md`（营销草稿） |
| `贡献指南.md` · `架构说明.md` · `插件开发指南.md` | `CHANGELOG-完整内部记录.md`（1393 行那份） |

判据只有一条：**陌生人打开它，能不能直接照着做一件事**。不能 → publish。

`docs/images/` 只留 README 真的在用的截图。一张图如果只有内部文档引用它，就跟着内部文档走。

## 这道闸门是测试，不是口头约定

`tests/test_code_health.py` 里两条，谁把内部文档推上来就红：

- `test_对外文档齐全` —— 该在的少了就红。
- `test_内部文档不许进公开仓库` —— `STATUS.md`、`计划/`、`变更说明-P*.md` 混进来就红。

**改规矩要改测试，不能只改这句话。** 只写不拦，等于没写 —— 上面那两次都是这么错的。

## 版权红线（最高优先级，任何理由都不破）

- **别人的游戏、别人的图、别人的音乐 —— 一律不进仓库，一次都不行。**
  「只放一个示例」「只是本地测试」都不是理由：推上去就是再分发。
- **MIT / 开源许可不等于随便放。** 许可要求保留版权声明和许可原文；塞进示例工程里
  很容易把声明弄丢，丢了就是违规。真要用，单独目录 + 完整 LICENSE 一起带。
- **NOTICE 里写了「不随仓库分发」的，就必须真的不在仓库里。** 文档和磁盘不一致要当场改。

## 编号：内部 P 号随便跳，对外版本只在发版时动（P117 起改的）

- 内部干活用 `P` 号，`P118` 后面直接跳 `P125` 也行 —— 那是我们自己的记账，不用连续。
- 对外**只有真发版**才动版本号。`rc` / `apk` 这种临时标记不进公开版本线。
- 发版必须写日志，写在 `CHANGELOG.md`，只写「下载新版的人能感觉到什么变了」，
  不写实现细节、不写内部流水账。四条必需：变了什么 / 为什么以前不行 / 验收数字 / 已知上限。

## 推之前问自己三句

1. **陌生人看到，会不会以为是我们的东西？** 会 → 别推。
2. **这个功能我自己用过三次吗？** 没有 → 放 publish 试，别拿仓库当试验田。
3. **推了之后，愿不愿意为它的每个 bug 负责？** 不愿意 → 别推。

## 现在各目录归哪层

| 目录 | 层 | 为什么 |
|---|---|---|
| `engine/` `editor/` `web/` `tests/` `android/` `brand/` `locale/` | 公开 | 引擎本体和自己的壳，缺了就跑不起来 |

| `作品/副产物/月光漫步` | **publish** | Ren'Py 的示例游戏，素材不是我们的 |

## 每次推之前跑一遍

```powershell
# 1. 有没有不该进库的东西混进来了（应为空）
git status --short

# 2. 有没有别人的作品躺在里面（应只出现自己造的示例）
git ls-files games 作品

# 3. 内部文档有没有混回 docs（应为空）
git ls-files docs | Select-String "STATUS|ROADMAP|BACKLOG|变更说明-P|计划"

# 4. 全量门禁（必须单独跑，别开两个）
$env:SDL_VIDEODRIVER="dummy"; $env:SDL_AUDIODRIVER="dummy"
py -3 -m pytest -q
```

四条都清白了才推。**推之前不看，等于让别人替我们踩雷。**
