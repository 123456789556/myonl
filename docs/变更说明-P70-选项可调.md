# P70 · 选项按钮真的能调了（三条断链）

> 症状：在编辑器「外观 → 选项按钮」里把宽度、圆角、颜色调成什么都行，手机端播放器一点变化都没有。
> 结论不是"少接一根线"，是**三条链同时断着**，任何一条没修都等于白调。

## 断链一：编辑器把配置写到了仓库根

`_ui_design_get` / `_ui_design_set` / `_ui_design_preview` 都用了 `self.app.project_root`。
用 `--script games\教程示例\script.gal` 启动时，`project_root` 是**启动目录（仓库根）**，不是剧本所在的作品目录，
于是外观页读到的是"空配置"（全默认 420/52/40/8），保存也写到根目录下并不存在的 config.json。

改：三处统一走 `_current_project_root()`（剧本所在目录），和素材扫描 `_get_assets` 用的是同一个解析。
验证：`GET /api/ui-design` 的 choices 从 `420/52/40/8` 变成作品里真实写的 `620/56/40/16`。

## 断链二：播放器根本不读 ui.choices

`web/myonl-player.js` 的 `drawChoices` 画的是 `L.choiceW / L.choiceH / L.choiceGap`（布局算出来的固定值），
圆角写死 `14`，底色写死两段渐变，文字色取主题 `vis.textColor`。config 里的 `ui.choices` 一个字段都没被读。

改：新增 `choiceGeom()`，七项全接上，且**默认值等于原行为**，没写这些键的老项目画面完全不变：

| 键 | 语义 | 手机端换算 |
|---|---|---|
| `width` | 按钮宽（1280 设计稿） | `L.choiceW * (width/420)`，夹在画布的 50%–94% |
| `row_height` | 按钮高 | `L.choiceH * (row_height/52)`，夹在 2.2–4.2 倍字号 |
| `gap` | 选项之间的缝 | `L.choiceGap * (gap/34)` |
| `dialog_gap` | 选项组离对话区多远 | 组中心 66% 高度上下浮动，夹在 42%–82% |
| `radius` | 圆角 | `radius * 1.6`，不超过行高一半 |
| `bg` | 按钮底色 | 有效 hex 即纯色覆盖渐变 |
| `fg` | 按钮文字色 | 空则跟随主题正文色 |

`dialog_gap` 与 `gap` 的语义按 pygame 端对齐（前者是"组与对话框的间距"、后者才是"选项之间的缝"），
所以老项目只写了 `gap: 20` 的时候，`dialog_gap` 走默认 40，位置不变。

## 断链三：单文件导出把 ui 和 dialogue 丢了

`engine/webpack.py` 的 `CONFIG_KEYS` 只有 `window_title / theme / colors / alphas / font / line_height`。
整段 `ui`（选项、快捷栏、菜单、设置页）和整段 `dialogue`（对话框贴图、透明度、内边距）在导出时被裁掉，
手机端读不到 —— 这解释了为什么"对话框皮肤导出的网页里没有"。

改：`CONFIG_KEYS` 加 `ui`、`dialogue`（config 全部加起来才几 KB，省这点没意义）。

## 编辑器这边

- 「选项按钮」组从 4 个滑块变 7 个：行宽 / 行高 / 选项组高度 / 圆角 / 选项间距 / 按钮底色 / 按钮文字色。
- 新增一块实时预览（300×132 画布，按手机竖屏 1080 宽等比缩放，`baseW 928 / baseH 137 / gap 34`），
  改任一参数立刻重画 —— 不用导出就能看见。
- 颜色留空 = 跟随主题（`placeholder` 里写明 `#202636 · 留空跟随主题`），后端只接受 `#rrggbb` 或空串，
  其它值直接丢弃不落盘。
- 控件全部 JS 注入（`editor/index.html` 卡在 600 行以内），HTML 只改了一处文案
  「距对话框（dialog_gap）」→「选项组高度（dialog_gap）」。

## 验收证据

  `choice-play-tuned-p.png`：紫底、绿字、大圆角、变宽变高、间距拉大，全部来自编辑器参数。

  （`test_p51_editor_ui_design` 的白名单断言同步扩到 7 键）。

## 已知副作用 / 未验证

- 老项目若写过 `width: 620`，手机竖屏按钮会从 0.86 宽变成 0.94 宽（夹到上限）——这是"改了就变"的正确表现。
- 编辑器点一次「保存」会把六组默认值一并铺进 config.json（前端全量提交，既有行为，未改），
  所以示例作品的 config.json 会出现几十行"等于默认"的键。
- 横屏选项页没有单独截图复验（几何走同一套换算，`dialog_gap=40` 时仍是 66% 高度，2×148+20 在 1080 高内不溢出）。
- 真机仍未验（`adb devices` 为空）。
