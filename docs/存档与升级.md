# 存档与升级

一句话：**桌面版升级不用管，网页版换位置要先导出，APK 覆盖安装不怕、卸载才会死。**

## 存档到底在哪

| 出口 | 存在哪里 | 升级时会不会被动 |
|---|---|---|
| 桌面版 | `%APPDATA%/Moyul/<游戏名>/`（`saves/slot_N.json` + `persistent.json`） | 不会。发行包**故意不带** `saves/` 和 `persistent.json`，解压覆盖只换程序文件 |
| 手机网页版 | 浏览器 localStorage：`myonl:v2:save:<hash36(标题)>-<hash36(剧本+槽位)>`、`myonl:v2:prefs` | 会 —— 它跟着 **origin** 走，换文件/换目录/换域名就换了一个 origin |
| 安卓 APK | 同一个 localStorage，origin 固定为 `https://appassets.androidplatform.net` | 覆盖安装不会；**卸载**会（连 app 数据一起清） |

桌面版在旧位置（工程目录下的 `saves/`）的老档，第一次启动新版时会**复制**一份到 APPDATA，原件不动 —— 所以老玩家升级不会丢。

## 为什么"换个文件名/换个目录就丢档"

这不是 bug，是浏览器规则：localStorage 按 **origin**（协议 + 域名 + 端口）隔离。

- `file:///D:/a/游戏.html` 和 `file:///D:/b/游戏.html` 是同一个 origin（`file://`），但很多浏览器把 `file://` 的 Storage 当临时数据，关掉就清；
- 用本地服务器打开 `http://127.0.0.1:8000/` 和 `http://127.0.0.1:9000/` 是**两个** origin，档互相看不见；
- 换成 `http://localhost:8000/` 又是第三个。

所以同一个 HTML 换个路径就等于换了台机器。**这不是我们能在播放器里修的**，只能靠"搬档案"绕过去。

## 三种场景怎么办

**1. 桌面版覆盖升级 —— 什么都不用做**
解压新包覆盖旧目录即可。档在 `%APPDATA%`，不在程序目录。

**2. 手机网页版要换文件/换目录 —— 先导出，再导入**
存档页底部有「导出」和「导入」两个按钮：

- 导出：生成一段 `MYONL1:` 开头的文本（约 1.4 KB），自动复制/下载成 `MYONL存档-<YYYYMMDD>-<HHMM>.txt`；
- 导入：把那段文本粘回去（或选文件），档原样写回当前 origin 的 localStorage。

对新位置重复一次「导入」，就搬过去了。**这是唯一可靠的跨 origin 搬运方式。**

**3. APK 更新 —— 覆盖安装不会丢**
只要新包和旧包的**签名相同**，就是覆盖安装，localStorage 原样保留。

签名不同时 Android 会拒绝覆盖，玩家只能先卸载 —— 卸载会清掉 app 数据，档跟着没。所以：
- 发布用的 keystore 只生成一次，之后每次打包都用它（`android/keystore/myonl-test.p12`，CI 里可被 `MYONL_KEYSTORE` 环境变量覆盖）；
- 万一真要换签名，提前让玩家「导出」一次，装完再「导入」。

**注意 origin 与包名无关**：壳把 assets 挂在固定的 `appassets.androidplatform.net` 上，所以换个 `applicationId` 也不会丢档。反过来说，同一个壳里装多个作品，档都在同一个 origin，靠 key 里的 `hash(标题)-hash(剧本|槽位)` 区分，不会串。

## 一条铁律

**卸载 = 删数据，覆盖 = 保数据。** 桌面版别手动删 `%APPDATA%/Moyul/`，APK 别卸载重装，网页版别直接换目录。非要动之前，先导出一次。
