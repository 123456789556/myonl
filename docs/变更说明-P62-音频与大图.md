# P62 变更说明：让声音真的响，让包别太大

P61 的单文件能发人了，但有两个窟窿，这轮补掉。

## 1. 音频：之前是哑的

`@music` / `@sfx` 在桌面端有声音，导到手机端**完全没声**——编译器根本没收集 `audio/`，播放器内核里 `music`、`sfx` 两个 op 落在 `default:` 分支，只记一句"暂不支持"就过去了。作者写了背景音乐，播出来是静音，也不会有人告诉他为什么。

改了三处：

| 位置 | 改动 |
| --- | --- |
| `engine/webpack.py` | 新增 `_collect_audio_names()`，扫 IR 里的 `music/track` 与 `sfx/sound`；`resolve_audio()` 找到就拷进 `assets/`，写进 `pack["audio"]`；单文件导出时音频也转 `data:audio/...;base64` |
| `web/myonl-core.js` | `music` → `{type:"music", track, fadein, fadeout}`；`sfx` → `{type:"sfx", sound}`；`state.music` 进存档 |
| `web/myonl-player.js` | 用 `Audio` 播（data URI 和 `assets/xxx.ogg` 同一个构造能吃）；切曲停旧曲、支持 `fadein`/`fadeout` 音量渐变；读档后把 `state.music` 续上；右上角一个静音键（逻辑坐标 ~43 屏幕 px，静音时音符上加斜杠，不是 ×——× 会被当成"退出"） |

`unsupported` 里也去掉了 `music` / `sfx`，现在只剩 `cg` / `video` / `camera` / `shake` / `anim` 这类真没做的。

**验证**：造了个带 `@music bgm_test fadein=0.5` + `@sfx se_click` 的临时工程，导成单文件后 `MYONL_DEBUG.audio` 显示 `paused=false, volume=1`（在响），点喇叭后 `muted=true`；`.ogg/.wav` 都成 `data:audio/...`。

## 2. 体积：base64 会让大图炸掉

单文件里图片是 base64，本身还要再涨 37%。一张 2 MB 的 AI 立绘 → 2.7 MB 文本，几张就能让手机打开时白屏几秒。

新增 `_shrink_image()`：**超过 300 KB 的图**缩到最大边 1600 内、转 WebP（quality 82）；压下来不到 10% 就不换（不值得）；没装 Pillow 就直接跳过（不让导出因此失败）。

实测一张 2400×2400 的噪声 PNG（16 MB）→ 单文件从不可用变成 **2 MB**，省 15 MB。

## 验证汇总

| 项 | 结果 |
| --- | --- |
| 音频收集 | `pack["audio"]` 有 2 条，`assets/bgm_test.ogg` 落地 |
| 音频内嵌 | 单文件里 `data:audio/ogg;base64,`，实际播放不静音 |
| 静音键 | 命中 → `muted=true`，点其他位置仍然翻页 |
| 大图压缩 | 16 MB → 1.5 MB，`data:image/webp` |
| 小图不动 | 40×40 图 `saved == 0`，仍是 `data:image/png` |
| 缺音频 | 不抛异常，名字进 `missing` |
| 教程示例 | 单文件 83 KB（比 P61 多 5 KB，是播放器里新增的音频逻辑），`unsupported` 为空 |
| 门禁 | 全量 `1082 passed + 1 skipped`；vm-smoke 新增 music/sfx/存档断言；微软雅黑/布局冒烟全过 |
| 发行包 | PyInstaller 打进 157 个 PIL 模块 + `_webp` 编码器（压缩功能在 exe 里也可用） |

## 边界

- 音频仍不压缩（ogg 本身已经很小；mp3 可以再降码率，没做）。
- 视频（`@video`）、CG 全屏（`@cg`）在手机端还是没实现，会如实进 `unsupported`。
- WebP 只用于单文件导出产物；分目录的网页包仍按原图拷（零转换铁律不变）。
