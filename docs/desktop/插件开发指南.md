# 插件开发指南（@plug: 指令扩展）

MYONL 支持**插件指令**：不改引擎核心代码，把一个 Python 文件放进剧本目录的
`plugins/` 文件夹，注册一个新指令，剧本里就能用 `@plug:指令名 参数` 调用它。

适合做：屏幕震动、成就系统、自定义演出、与外部数据联动……任何 `@set` / `@show`
表达不了的自定义行为。

## 一、最小例子

```python
# plugins/boom.py
from engine.runtime import register_command

def _boom(state, args):
    return {"type": "plug:boom", "args": args}

register_command("boom", _boom)
```

剧本里：

```
@plug:boom 烟花 大号
```

## 二、目录与加载规则

- 位置：`<游戏目录>/plugins/*.py`，文件名排序、逐个 import；
- 模块顶层调 `register_command` 即注册；同名重复注册 → 覆盖，后注册生效；
- 加载失败只打警告（`[插件警告] 加载 plugins/<文件> 失败：…`），不崩游戏；
- 剧本目录下没有 `plugins/` 文件夹，或文件夹为空：不加载，无副作用。

## 三、handler 签名

```python
def handler(state: dict, args: list[str]) -> dict | None
```

| 参数 | 说明 |
|---|---|
| `state` | 当前 `GameState` 快照 dict（可读写里面的 `vars` / `sprites` / `music` 等） |
| `args` | 指令后面的参数，按空白切分的字符串列表 |
| 返回 `dict` | 作为事件进 trace，播放器可收到（自动附 `seq`） |
| 返回 `None` | 静默：只改 state，不产生事件 |

返回值不是 dict / None 时，运行时打 `[插件错误]` 并回一个 `plug:error` 事件，游戏不崩。

## 四、能碰什么、不能碰什么

**可以**：读写 `state["vars"]` 存成就 / 标记；读 `state["sprites"]` / `state["bg"]` 做条件演出；
调标准库读本地数据（注意路径安全，别把玩家传进来的字符串直接拼文件路径）。

**不要**：在 handler 里起常驻线程 / 网络服务；直接 import pygame 画东西（演出效果应通过
事件交给渲染层）；在模块顶层做重活（顶层只做 `register_command`）。

## 五、在剧本里用

```
@choice:
  > 点燃烟花 -> end_good
  > 算了 -> end_bad

@label end_good
@set 成就_烟花 = 1
@plug:boom 烟花 大号
@ 夜空炸开一朵。
@end
```

`@plug:指令名 空格分隔的参数…`，参数原样进 `args`；需要多词参数时在插件里自行拼接。

## 六、调试与测试

- 看 stderr：加载失败 / handler 抛异常 / 返回值类型错，都会打 `[插件警告]` / `[插件错误]`。
- 测试参考 `tests/` 里插件相关用例：构造 `Runtime`、放一个临时 `plugins/` 目录、跑一条
  `@plug:` 指令，断言 state 或事件。
- 引擎侧插件注册表是进程内的；测试之间不共享注册结果。

## 七、边界说明

- 插件只在电脑端 Python 运行时加载。手机端解析器不执行 `@plug:`（见 [手机端编游戏](../mobile/手机端编游戏.md)
  与 [engine_spec.md](../engine_spec.md) §2.9）。
- 插件是**开发期**能力，只在电脑端 Python 运行时加载。`plugins/*.py` 不会被任何打包路径带进成品——`tools/pack_apk.py` 只换 `assets/game.html`，`engine/` 的打包也不拷 `plugins/`；成品里没有 Python 解释器，插件自然也不存在。要发给别人玩，就别依赖插件。
