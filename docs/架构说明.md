# 架构说明（代码怎么组织）

> 面向：以后接手的自己、想改引擎的开发者、评审代码的人。
> 只讲**结构**与**数据流**；语法看 [engine_spec.md](engine_spec.md)，使用看 [开发者使用指南.md](开发者使用指南.md)。

## 一、一句话架构

```
script.gal ──parser──> 指令列表 list[dict]
                         │
                         ▼
                    runtime（GameState / 事件）
                         │  snapshot()
                         ▼
                    renderer（10 个 render_* Mixin）
                         │
        ┌────────────────┼─────────────────┐
        ▼                ▼                 ▼
    pygame 窗口      demo 主循环       编辑器截图/预览
```

编辑器是**旁路**：它只读写磁盘上的 `.gal` / `config.json` / 素材，再调用上面的解析/渲染做预览，不参与游戏运行时。

## 二、目录与模块职责

### engine/（引擎核心，12.6k 行）

| 模块 | 职责 | 备注 |
|---|---|---|
| `parser.py` | `.gal` → 指令列表；语法校验、`@include` 展开、`dump_text` 回写 | 纯函数式，不碰 pygame |
| `expr.py` | `@set` / `@if` 的表达式求值 | 白名单，禁止属性访问/导入 |
| `runtime.py` | 解释器与 `GameState`：执行指令、分支、变量、存档锚点、插件命令 | 只产出事件，不绘制 |
| `save.py` | 10 槽 + 快存、缩略图、全局解锁 | 原子写 |
| `config.py` | 引擎默认值 ← 项目 `config.json` ← 玩家 `settings.json` | 三层隔离 |
| `data.py` | 资源定位（图片/音频/字体）、`settings.json` 读写 | 路径安全 |
| `ui.py` | UI 状态机：标题/菜单/存档/设置/回看/画廊；只导出 view dict | 业务动作由 demo 执行 |
| `renderer.py` | 渲染入口；组合下面 10 个 Mixin | **严格 ≤700 行** |
| `render_scene.py` | 背景/视频/前景/转场/相机/章节卡/CG | |

## 三、一次运行发生了什么

1. `demo.main` 读 `config.json` + `settings.json`，建 `Renderer` 与 `UI`。
2. `Runtime.load(script)` → `parser.parse_file` 得到指令列表，建立标签表。
3. 每帧：`runtime.step()` 执行一条指令并产出事件 → `runtime.snapshot()` 给渲染层。
4. `renderer.render(state, ui.view())`：先合成场景层（背景 < 立绘按 z < 前景），再叠转场/对话框/UI 覆盖层。
5. 玩家输入：`ui.handle(key)` 返回业务动作（开始游戏/存档/设置变更），由 `demo` 执行。

编辑器预览走同一套：`editor._preview_png` 用 dummy 视频驱动跑前 N 帧，直接截图返回 PNG；场景视图的「真实渲染预览」也调用它。

## 四、扩展点（不碰内核）

| 想加什么 | 改哪里 |
|---|---|
| 新剧本指令 | `parser._one` 加分支 + `runtime` 执行 + `engine_spec` 文档 + `tests/test_parser.py` |
| 新演出效果 | 新建 `render_xxx.py` Mixin，在 `renderer.py` 组合；行数 ≤700 |
| 外部能力（成就/网络） | 插件：`plugins/xxx.py` + `register_command`，剧本写 `@plug:xxx` |
| 新 UI 布局 | `config.json` 的 `dialogue` / `ui` 段；玩家侧覆盖走 `settings.json` |
| 新工程模板 | `engine/newgame.py` 的 `TEMPLATES` + `_create_*_skeleton` |
| 新素材 | `tools/make_builtin_assets.py`（内置）或 `tools/import_assets.py`（批量导入） |

## 五、硬约束（测试会拦）

- `engine/render_*.py` 与 `renderer.py` 单文件 ≤700 行；`editor/index.html` <600 行。
- 每个测试文件必须声明 `pytestmark`（`unit/ui/slow/integration` 至少一个）。
- 类型检查是棘轮：只拦新增，基线见 `tools/pyright-baseline.json`。
- 覆盖率门禁：`engine/` ≥80%。

## 六、已知边界（别当成 bug）

- 仅 Windows（依赖 pygame 窗口 + WebView2）；不内置遥测，游戏存档与素材全部本地离线保存。
- `pyright` 仍有存量错误（基线内），类型并非全绿。
- 运行时视频只支持帧序列 PNG，不支持任意编码视频（A5 待评估）。
- 角色库是可选高级功能；不登记也能用 `@[角色]` 台词。

## 七、新人阅读顺序

1. `docs/快速上手.md` → 跑起来；
2. `docs/engine_spec.md` §1（架构图）+ §2（指令表）；
3. `engine/parser.py` → `engine/runtime.py`（先看 `step` 的主 `while`）；
4. `engine/renderer.py`（组合关系）→ 需要哪个效果再看对应 `render_*.py`；
5. 改前端从 `editor/editor_scene.js` 入手（注释最全，交互最完整）。
