# 打包使用指南（把作品发出去）

> 目标：做好的作品怎么变成别人能拿到、能打开玩的成品。
> 三条出口，按玩家在哪选；**APK 是主出口**，单文件 HTML 是通用出口，Windows 目录包是辅助。

## 0. 三条出口对照

| 出口 | 产物 | 谁能玩 | 在哪做 | 要不要 Python |
|---|---|---|---|---|
| 单文件 HTML | 一个自包含 `.html`（播放器 + 剧本 + 素材内联） | 任何现代浏览器，手机 / 电脑都行 | 手机编辑器「导出」；电脑端 `build_single` | 手机端不要；电脑端要 |
| 安卓 APK | 一个安装包，手机 / 安卓平板同一个包 | 安卓 7.0+ | GitHub Actions（`.github/workflows/android-apk.yml`），不在本机打 | 不需要作者本机配 SDK |
| Windows 目录包 | 文件夹（exe + 资源外置） | Windows 双击即玩 | 电脑端 `pack.py` / 发行版编辑器 | 源码打包要；发行版内置运行库不要 |

> 不做 iOS。网页包在 iOS 浏览器里能打开，但没有 iOS 安装包。

## 1. 单文件 HTML（最通用）

### 手机 / 平板上直接出

编辑器底部「导出」：本机用 `engine/parser.js` + `engine/pack.js` 把剧本和素材拼成一个
自包含 `.html`，走系统「保存到」落盘。发微信、发 QQ、传电脑，对方浏览器打开就能玩。

### 电脑端出

```powershell
py -3 -c "from engine.webpack import build_single; build_single(r'games\我的游戏', r'dist\web\游戏.html', title='游戏')"
```

### 体积与上限

- 素材内联成 base64，体积比原图再胖约三分之一（37%）。
- **40 MB 软提醒**，**80 MB 硬线**：两条线都只做强提示、不硬拦导出（作品不该被打包门卡死）；
  但超 80 MB 后低端机要先把整个文件读进内存才显示第一句，大概率白屏或闪退。超线就先缩图、拆章，
  不要硬塞几百 MB 原图。手机端编辑器界面上会直接看到这条告警，电脑端口径一致。
- 更大素材的「文件夹 / zip 发行」（图放旁边、HTML 引用）还没做。

## 2. 安卓 APK（主出口）

APK 由 CI 从 tag 构建：WebView 壳 + 内置编辑器（`editor-single.html`）+ 播放器内核 + 内置示例。

- `minSdk 24`（安卓 7.0），一个包装手机和安卓平板，横竖屏按屏幕重排。
- 签名固定在一个 keystore 上，覆盖安装不清数据；升级为什么不毁档见 [存档与升级](存档与升级.md)。
- 作者本机不需要配 Android SDK：打 APK 是 CI 的事。本机改完代码、提 tag，CI 出 release 包。
- **分享与打开入口**：导出成品后，壳内可直接「发给朋友」（FileProvider + `ACTION_SEND`）；
  别人发来的作品文件，可用本应用「打开」（`ACTION_VIEW` 接到已有导入链路）。
  这两条入口当前**未在真机编译验证**（本机无 Android SDK），行为以 CI 出包后的实测为准。
- **版本号**：tag 发版走语义码 `MAJ*10000 + MIN*100 + PAT`；手动触发（workflow_dispatch）或
  分支构建走单调递增的运行号当 versionCode，不再恒为 1，覆盖安装能分出新旧。
- **v1.2.0 包体积构成**（Release 资产实测，压缩后口径）：`classes.dex` 1,447,109 B（66.15%，壳 Java +
  androidx + Kotlin 运行时）、`assets/game.html` 347,029 B（15.86%，内置示例）、`assets/index.html`
  215,588 B（9.86%，编辑器主体）；`lib/` 下 0 个 `.so`、0 个 ABI（不依赖 NDK 原生库）；签名为
  v2/v3 Signing Block（约 4 KB），zip 内无 v1 JAR 签名的 `.RSA/.SF/MF`。

## 3. Windows 目录包（辅助，仅 Windows）

把作品打成玩家双击即玩的文件夹，资源外置、可替换。

### 准备环境（只需一次，源码打包）

1. 装 Python 3.9 或更高，安装时勾选「Add Python to PATH」。
2. 在仓库目录打开命令行：

```powershell
pip install -r requirements.txt
pip install pyinstaller
```

### 整理游戏目录

一个可打包的游戏目录至少包含 `script.gal`，推荐结构：

```
我的游戏/
├─ script.gal          剧本入口（必须）
├─ images/            背景、立绘（png/jpg/jpeg/webp）
├─ audio/              音乐、音效、配音（ogg/mp3/wav）
├─ fonts/             中文字体（建议放一个，避免别的电脑上中文变方块）
└─ plugins/            插件（*.py，可选）
```

### 执行打包

```powershell
py -3 pack.py games/我的游戏
py -3 pack.py games/我的游戏 --name 示例游戏
py -3 pack.py games/我的游戏 --bump patch
```

- 第一个参数：游戏目录；`--name`：游戏名（决定 exe 文件名与产物目录名，省略时用目录名）；
  `--bump patch/minor/major`：在 `pack_config.json` 上迭代版本号。

产物在 `dist/<游戏名>/`：`<游戏名>.exe` + `_internal/` + 剧本 / 资源 / 插件。
**不要把 exe 单独拖出来**，它依赖同目录的 `_internal/` 和资源文件。

### 发给玩家

把整个 `dist/<游戏名>/` 文件夹压成 zip 发出去。玩家解压到任意位置（避开需要管理员权限的
`Program Files`），双击 exe 即可；存档生成在 exe 旁的 `saves/`。玩家电脑不需要 Python。

## 4. 资源与插件（可见、可替换）

| 目录 | 放什么 | 能否替换 |
|---|---|---|
| `script.gal` | 剧本 | 可以（替换后重开游戏生效） |
| `images/` | 背景、立绘、前景、CG | 可以（同名覆盖） |
| `audio/` | 音乐、音效、配音 | 可以（同名覆盖） |
| `fonts/` | 中文字体 | 可以（`.ttf/.ttc/.otf`，引擎优先使用） |
| `plugins/` | 插件脚本 | 可以（放入 `*.py` 后重开游戏生效） |
| `saves/` | 玩家存档 | 删除即清空存档，备份即转移进度 |

资源原样复制进产物，没有加密、没有中间格式，方便更新与二次创作。

## 5. 常见问题

**Q：中文显示成方块？**
把中文字体放进游戏目录的 `fonts/`（如 NotoSansCJK）再重新打包。

**Q：双击 exe 提示「找不到剧本文件」？**
exe 必须和 `script.gal`、`images/`、`audio/` 放在同一个目录，不要把 exe 单独拖出来。

**Q：重新打包会不会覆盖玩家存档？**
会。`pack.py` 每次重建 `dist/<游戏名>/`，发新版本前先备份该目录下的 `saves/`，打包完再复制回去。

**Q：能打包成单个 exe 吗？**
当前固定 onedir（资源外置、存档可见、杀软误报少），不提供 onefile 模式。

**Q：杀毒软件拦截 exe？**
PyInstaller 目录模式比单文件误报少，但个别杀软仍可能拦。把产物目录加入信任区即可。

## 6. 仓库自带示例

`games/` 下四个工程，全是自造占位素材：

- `教程示例` —— 指令怎么用，一句一句标好了
- `标准示例` —— 一个完整工程：剧本、素材、配置齐全
- `新游戏模板` —— 从空的开始，只剩骨架
- `newbie_demo` —— 打进 APK 的示例工程（首页已不露「试玩」入口，改成「新手教程」现场建一份短作品；这个工程仍是 CI 出包时的作品模板与示例素材来源）

```powershell
py -3 pack.py games/标准示例 --name 我的游戏
```
